# 三生小说创作 · 系统设计

> 独立的交互式小说创作因果伙伴系统。内置道一34行引擎，加载六道因果络的领域映射。
> 作为独立 skill（`sansheng-novel-creation`）运行，不依赖 `sanshengwanwu`。
> 不是写作工具——是因果镜子。帮作者看清笔下人物在18条因果路径上的张力。
> 记录于 2026-06-28。

---

## 〇、一句话定义

**作者提供意图和文本 → 系统在18条因果路径上反射张力 → 作者看到因果后做出选择 → 循环。**

系统不教作者怎么写。系统只做一件事：**把因果放到共同焦点上，让作者自己看。**

---

## 一、系统架构：独立 skill，自包含

```
用户（作者）
  ↓ 意图 + 文本     ↑ 因果镜子反馈 + 分支推演
┌──────────────────────────────────────────────┐
│       sansheng-novel-creation SKILL          │
│                                              │
│   阶段一：大纲生成                            │
│   阶段二：角色设计（JD-R 档案 + memories）     │
│   阶段三：逐章因果镜子                        │
│   阶段四：全书因果审计                        │
│   阶段五：分支推演（内置道一引擎）              │
│                                              │
│   交互协议：提问在道内                         │
│   （Collins 互动仪式：共同焦点=因果张力）       │
└──────────┬───────────────────────────────────┘
           ↓                    ↓
┌──────────────────┐  ┌───────────────────────┐
│ domain_knowledge/ │  │ 道一34行引擎（内置）    │
│ 小说创作.md       │  │ Character.tick()      │
│                  │  │ pool + memories        │
│ 18条路径叙事语义  │  │ 概念运行（非实际Python） │
│ 心之壁判定        │  └───────────────────────┘
│ 交互协议细节       │
└──────────────────┘
```

- **领域知识（`domain_knowledge/小说创作.md`）**：18条路径的叙事诊断问题 + 不合道信号，心之壁判定表，报告模板
- **道一引擎（内置）**：为每个核心角色建立一个 `Character` 实例。每次情节推演在概念层跑 `tick()`。不产生Python代码，Agent在推理时模拟。
- **分支推演**：引擎直接在 skill 内使用——不依赖 `sanshengwanwu` skill

## 二、四阶段工作流

### 阶段一：构思 → 大纲生成

**输入**：作者描述故事方向（题材、主题、大致剧情、关键情节点）

**系统做什么**：

1. **识别核心冲突**：主角在和什么对抗？（外部敌人 / 内部困境 / 社会结构 / 命运）
2. **映射到子系统一（JD-R）**：主角的消耗源是什么？
   - ⑤表面呈现：在谁面前演戏？内外距离多大？
   - ⑦认知负荷：需要算计/记多少秘密？
   - ⑦'生理消耗：身体的代价（战斗、奔波、伤病）？
   - ⑨前台维护：维持"我是谁"的成本？
3. **映射到子系统二（Collins）**：主角的互动仪式链在哪些场景建立？哪些场景断裂？
4. **设定心之壁**：叙事渗透性——读者能看到多少内心？
5. **生成大纲初稿**，每个情节点标注它触发的因果路径

**交互示例**：

```
系统：大纲中[重逢场景]触发路径①（前台↔互动）。
角色A在这个场景中展现的样子，和读者已知的内心一致吗？

作者：不一致。A其实不想见B——但表面上要装得满不在乎。

系统：这会在路径⑤（表面呈现→消耗）产生消耗。你在本章还是后面章节
让读者感知到"装"的代价？两种节奏的因果效果不同。
```

### 阶段二：角色设计 → JD-R 档案 + 道一引擎状态

**输入**：作者描述角色（性格、背景、创伤、动机）

**系统做什么**：

1. 为角色建立 JD-R 档案

| JD-R 维度 | 小说映射 | 填入 |
|-----------|---------|------|
| Emotional Demands ⑤ | 在谁面前需要"演"？ | |
| Cognitive Demands ⑦ | 动脑子的负担多重？ | |
| Physical Demands ⑦' | 身体承受什么？ | |
| Psychological Demands ⑨ | 维持"我是谁"的成本？ | |
| Social Support ⑤' | 谁能接住他？ | |
| Performance Feedback ⑥' | 什么让他觉得"我做对了"？ | |
| 边界渗透性 | 读者能看到多少内心？ | |
| 元认知水平 | ①↺'的路径选择：A（内化）还是 B（工具）？ | |

2. 将背景故事转换为道一引擎的 `memories` 列表

```python
# 示例：背负血仇的剑客
swordsman = Character()
swordsman.pool = 0.4  # 初始消耗——长期高负荷
swordsman.memories = [
    {"emb": encode("家族灭门"), "intensity": 0.9},    # 核心创伤
    {"emb": encode("师父收留"), "intensity": 0.7},    # 正向锚点
    {"emb": encode("第一次杀人"), "intensity": 0.6},   # 道德消耗
    {"emb": encode("仇人现身"), "intensity": 0.8},     # 仇恨触发
]
```

3. 展示角色的"因果拓扑"——什么事件会激活什么记忆，什么记忆之间互相放大消耗

### 阶段三：逐章写作 → 交互式因果镜子

**核心原则**：系统不是审查者——是协作伙伴。提问在道内。

**每章流程**：

```
作者提交文本
     ↓
系统读取 → 感知因果张力
     ↓
系统以合道方式呈现张力
     ↓
作者选择：
  · "对，我这样写没问题" → 下一章
  · "你说得对，我补一段" → 修改后循环
  · "我不确定" → 分支推演 → 选一条线 → 下一章
```

**提问的四种仪式形态**：

| 仪式类型 | 触发条件 | 提问形式 |
|---------|---------|---------|
| **呈现** | 感知到因果张力 | "我看到 X 做了 Y，但上一章 Z 刚发生。这两个事件之间的因果联系，读者在本章能感知到吗？" |
| **好奇** | 不确定路径状态 | "这个角色是真的在平静，还是在撑？如果是撑——你想让读者现在就感知到，还是埋到后面一次性爆发？" |
| **镜像** | 作者在两个方向间犹豫 | 触发三生万物分支推演——展示每条线的 pool 曲线和因果后果 |
| **沉默** | 因果密度充足，无张力 | 不说话："本章因果链路通畅" |

**提问的禁忌**：

- 不说"你应该……"——系统不教作者怎么写
- 不说"这段不合道"——因果不是对/错标准
- 不用路径编号和框架术语——作者不需要知道眼镜的牌子

### 阶段四：全书回望 → 全局因果审计

全书完成后，系统读取全部文本：

1. **全局 pool 轨迹审计**：每个核心角色的内部状态曲线是否有因果断点？
2. **慢变量路径检查**：①↺'（自我认知偏移）、⑧（外部塑形）、⑨（前台维护成本）在全书的月/年跨度上是否在推进？
3. **跨章因果跳跃标记**：有些跳跃在逐章写作时不易察觉——全书回望时才显现
4. **全局资源因果闭环**：获得的所有重要资源是否都有了叙事后果（路径⑬闭环）？

## 三、三生万物在创作中的使用

### 接入时机

| 时机 | 场景 | 怎么用 |
|------|------|--------|
| **创作犹豫** | "角色应该原谅还是决裂？" | 两条分叉线，并排展示 pool 轨迹、激活的记忆、交叉传播强度 |
| **回顾验证** | "这个创伤真的改变了角色吗？" | 克隆角色但不注入该事件，对比长期 pool 差异 |
| **冲击测试** | "在第 N 章加一场巨大冲击——角色扛得住吗？" | 注入高 intensity ERF 事件，观察 pool 跌落深度和恢复曲线 |
| **节奏诊断** | "连续高强度行动了多章，是不是该低谷了？" | 统计连续高 drain 轮次，预测⑥崩塌窗口 |
| **后日谈模拟** | "完结后角色假如再遇到……" | 用全书的最终 memories 状态，注入假设的未来事件 |

### 输出语言转换

引擎输出的是数字，呈现给作者的是因果语言：

```
引擎：T5 pool=0.24, 激活=[背叛(0.9), 灭门(0.8)], 交叉传播=0.12

转换为：
到第五章，角色的内部消耗已经非常深了。
旧伤（背叛、灭门）同时被触发——两件事在互相放大痛苦。
如果读者感受不到这种"旧伤叠新伤"的沉重，
后面角色的崩溃会显得突兀。
```

## 六、核心洞见（这个系统的"道"）

1. **人物的行为从内部状态自然生长出来**——这不是艺术教条，是因果网络的形式化描述。18 条路径不是在教怎么写——是在帮作者看：你写的人物行为，在因果层面跑得通吗？

2. **提问本身在道内**——系统向作者提问是一次 Collins 互动仪式。共同焦点是因果张力，共享情绪是"一起琢磨"。仪式成功 → 作者感到被理解（路径②互动→关系积累）。仪式失败 → 系统变成了评判者（路径⑩期望违背）。

3. **眼镜不进世界**——六道因果络是因果检测框架，道一是推演引擎。作者的文本是 glasses 的输入，引擎是该角色在未来事件中的反应模拟。三者分离：分析语言不入引擎，引擎数字不入作者界面，作者不被框架术语污染。

4. **沉默也是互动**——因果密度充足时，系统不说话。沉默的确认（"本章因果链路通畅"）本身是一次仪式成功——比强行点评更符合道。
