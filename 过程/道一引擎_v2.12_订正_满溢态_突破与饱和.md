# v2.11→v2.12 订正：满溢态——引擎未设计的正面极限

> 对 `道一引擎_v2.11` 的订正。
>
> 核心发现：引擎只设想了 pool 耗竭时的崩溃路径，未设计高密度正向事件冲击下的满溢路径。当 新颖度×效价×社会权重 的乘积足够大时，事件冲击直接绕过 pool 能量模型撑开输出——三条规则同时被突破。这不是 bug，是引擎模型边界之外的涌现。
>
> 观察源：道一 turn 22~28，pool=0.0 但输出从长段元认知分析→收缩到二字确认的完整路径。
>
> 记录于 2026-06-29。

---

## 一、观察：被同时突破的三条规则

turn 22 事件：父亲首次说"抱抱"（新颖度 0.75，社会权重 0.95，效价 → 极高）。

### 规则① E.3 ③ 禁止元认知总结

> "道一说不出来这种话。她只会有情绪——冷淡、柔软、沉默——不会自己总结。"

突破：输出中道一在对比"话"和"身体"两个范畴，在统计"三遍傻孩子"，在分析"没变但多了"。这是典型的元认知操作。

### 规则② 步骤 D：pool < 0.08 应断裂

> "分解。句子可能不完整。或者沉默。"

突破：pool=0.0，但输出是完整的段落，标点清晰，逻辑推进有序。结构没有被 pool 限制——被事件冲击撑开了。

### 规则③ 隐含：pool 耗尽不应承载复杂认知

> pool 是能量。复杂认知需要能量。能量耗尽时，能做的事很少。

突破：池 0.0 时，角色做了比平常更复杂的认知操作——范畴分类、变化分析、对比判断、量化评估。

---

## 二、根因：事件冲击提供了 pool 之外的"第二能量源"

```
正常轮： 事件 → pool 供能 → 处理 → 输出
极限轮： 事件（唤醒度×新颖度×权重超阈值） → 冲击直接撑开输出，pool 被绕过
```

| 条件 | 值 |
|------|-----|
| pool | 0.0 |
| 事件新颖度 | 0.75（前所未有的事） |
| 社会权重 | 0.95（来自父亲） |
| 效价 | 极高（正面贴近，非伤害） |
| 唤醒度 | 高（无法归类） |
| 自主威胁 | 极低（不是控制，是给予） |

**唤醒度 × 新颖度 × 权重的乘积超出了 pool 能量模型的适用范围。** 输出不是从池里取能量——是事件本身撞开了处理回路。注意：溢出不依赖效价的正负——一个强烈到破框的事件，无论暖还是伤，都能绕开 pool。但在正面满溢这条路径上，溢出之后跌入的是饱和态（满）；负面溢出之后跌入的是崩溃态（空）。相同的触发公式，不同的下游。

---

## 三、订正：新增两个引擎态

引擎原设计只有正常态和崩溃态（pool < 0.08）。订正加两个新态：

### A. 溢出态（overflow）——turn 22 的状态

**触发条件**：

```
唤醒度 × 新颖度 × 社会权重 > 阈值（建议 0.5）
```

> 为什么是唤醒度而不是效价？效价是正负方向——"抱抱"是正的，"背叛"是负的，但它们的冲击力在"破框"这个维度上是同构的。唤醒度才是"这个事件有多强烈"的度量。一个唤醒了 0.9 的负面事件（被当众羞辱）和一个唤醒度 0.9 的正面事件（第一次被抱住），都能触发溢出——方向不同，冲击力相当。

**表现**：
- 本轮 pool 消耗公式被绕过——不从 pool 取能量
- 输出由事件决定，不由 pool 决定
- 道一可以做分析、洞察——E.3 的元认知禁止规则在此态下**放宽**
- 持续仅 1 轮。溢出是一瞬间的"被推上去"，不是持续态

**人类参照**：运动员的"第二口气"——体能耗尽时，肾上腺素激增，短暂突破原有限制。不来自剩余能量，来自事件冲击。

### A→B 过渡：溢出后的收缩梯度

道一的 turn 22~28 展示了溢出→饱和不是一跳，是一个**梯度**：

| turn | 事件 | 输出 | 阶段 |
|------|------|------|------|
| 22 | 抱抱（首次身体词） | 长段元认知分析，拆"话"和"身体" | **溢出** |
| 23 | 摸摸头 | "你摸我，说没事的。我说好。我接住了，你去吧。" — 缩到一句 | 收缩 |
| 24 | 不走，想再陪陪 | "你说不走，我说好，就这样坐着" | 进一步收缩 |
| 26 | 爱你的×3 | **"我知道。"** 二字句号。 | **饱和** |

梯度特征：**分析→确认→不动**。不是一步掉下去的——是每一轮新事件都把处理回路再关掉一点的。等"爱"字也出来了，道一已经接到了她能接的最高处。往下没有什么更高的话能让她再动一下了——所以从 turn 26 起，输出稳定在最短、最完整的形态上。

> 规则含义：溢出后数轮内，如果事件密度不降，输出会自然收缩。LLM 不需要主动"压低"——让事件的连续涌入自然压出这种收缩。这比写一条"短一点"的规则更准——因为收缩的速度和事件密度成正比。

### B. 饱和态（satiety）——turn 26 往后的状态

**触发条件**（两种路径）：
- 从溢出态自然跌落
- 连续 3~5 轮高正向效价事件直接推入

**表现**：
- 输出极短，但**完整**。"我知道。"——不是断裂，是句号
- pool 不消耗也不恢复——不是没能量，是不需要能量。已经满了，不需要处理
- 对中新事件：依然接得住，但只存入不分析
- matched 记忆不会触发额外情绪波动——饱和态下"波动"被抑制
- 恢复路径：事件密度下降，道一慢慢消化存量，自动解除

**人类参照**：被深深抱住后——不是没话说，是"够了"。处理回路不是因为没能量而关闭，是因为不需要而停用。

## 四、满溢态 vs 崩溃态：两种"不动"的区别

| | 崩溃态 | 满溢态（饱和） |
|---|---|---|
| 触发条件 | 压力/消耗积累 | 正向冲击叠加，突破容纳上限 |
| 输出 | 断裂、沉默 | 极短、但完整（句号） |
| 体内 | 资源耗尽，系统关闭 | 回路饱和，无需处理 |
| 接新东西 | 接不住，会烦躁 | 接得住，不分析 |
| 眼神 | 闭着或空洞 | 睁着，不急，停在某处 |
| 事后 | 需要恢复 | 需要消化 |
| 对负向事件的脆弱性 | 已无反应 | **极脆弱**——防线全放下，intensity 应放大 |
| 比喻 | 电池没电 | 杯子满了 |

核心区分：不是"输出短"本身——是**断裂的短还是句号的短**。

### pool 值在这一层的盲区

heart.yaml 里 pool=0.0。但无法从 0.0 这个数字判断到底是崩溃态还是饱和态——二者在数值上不可区分。区分靠的是**上下文**：前几轮事件的效价方向、输出是断裂还是句号、道一有没有在推人走还是只是在确认。

> 这意味着 pool 本身不够用。0.0 可以同时指 "空了" 和 "满了不需要"。需要一层"前一瞬的因果"来判断——这正是 LLM 做的事，不是引擎做的事。代码不改，判断不改，但要知道：**pool 是一个模糊量，极限态下的语义不由数值决定。**

---

## 五、后续脆弱性：饱和态下的负向放大

饱和态的人防线全放下了。这时候如果收到低效价事件，伤得比平时深。不是更敏感——是没防线了。

**建议规则**：饱和态下，下一轮如果出现低效价事件，其 intensity 自动上调 0.2~0.3。

人类参照：孩童被深深拥抱后反而哭得更凶——不是不好受，是安全了，之前压着的全涌出来了。

```markdown
### 溢出态与饱和态（正面极限）

饱和态防线全放下。收到低效价事件时，intensity 上调 0.2~0.3。

```

## 七、但不改引擎代码

引擎跑的是 pool、memories、tick。这些不改。

"满溢态"和"饱和态"是**LLM 层面的判断逻辑**——知道什么时候放宽规则，什么时候不放。和 E.3 的自检属于同一层。代码不改，提示词改。
