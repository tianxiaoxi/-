## Phase 1：全球主播筛选与素材归档

### 1.1 筛选目标

通过 WebSearch 在线搜索，覆盖**全球各国家/地区/语言**的虚拟主播/直播主播，**不限制数量**——只要公开信息足够支撑六维分析，全部纳入。

| 目标 | 说明 |
|------|------|
| 覆盖范围 | B站（中国）、YouTube（全球）、Twitch（欧美/东南亚）、Niconico（日本）、抖音/TikTok、AfreecaTV（韩国）等主流平台 |
| 数量策略 | **不设上限**——不做"每个类别至少N人"的限定，而是"搜到多少符合条件的就纳入多少" |
| 语言 | 中文、日文、英文、韩文搜索词并用，搜索结果的语言不限 |
| 筛选标准 | 仅排除"公开信息不足以支撑六维分析"的主播（无粉丝数、无近期动态、无讨论帖） |

---

### 1.2 筛选维度（六维交叉分类）

#### A. 地域/语言

| 类别 | 说明 | 搜索语言 |
|------|------|:---:|
| **中国大陆** | B站VUP/虚拟主播 | 中文 |
| **日本** | YouTube/Niconico VTuber | 日文+中文+英文 |
| **英语圈** | YouTube/Twitch EN VTuber | 英文 |
| **韩国** | YouTube/AfreecaTV/Chzzk | 韩文+中文 |
| **东南亚** | YouTube VTuber（印尼/泰/越等） | 英文+中文 |
| **其他地区** | 欧洲、拉美等 | 英文+当地语言 |

#### B. 从业状态

| 类别 | 说明 |
|------|------|
| **现役·活跃期** | 近期（2025-2026）频繁直播，公开讨论多 |
| **现役·瓶颈期** | 仍在直播但出现倦怠/停播/转型信号 |
| **退役/休眠** | 已明确毕业、停止活动或长期休眠 |

#### C. 从业时长（经验分层）

| 类别 | 说明 |
|------|------|
| **新人期（0-6个月）** | 首播不久，人设在建立中 |
| **成长期（6个月-2年）** | 有稳定粉丝群但还在上升 |
| **成熟期（2-5年）** | 行业知名，人设固化 |
| **超长待机（5年+）** | 行业元老，经历过完整周期 |

#### D. 内容类型

| 类别 | 说明 |
|------|------|
| **歌势** | 以唱歌/音乐为核心内容 |
| **杂谈势** | 以聊天/互动/情感陪伴为核心 |
| **游戏势** | 以游戏实况/竞技为核心 |
| **知识/教学势** | 以知识分享（语言/物理/音乐教学等）为核心 |
| **综合势** | 多种内容混合，无明显单一标签 |
| **ASMR/特殊** | ASMR、朗读、手作等小众类型 |

#### E. 规模层级（平台自适应）

| 类别 | B站（粉丝） | YouTube（订阅） | Twitch（关注） |
|------|----------|--------------|-------------|
| **顶级** | 300万+ | 300万+ | 100万+ |
| **头部** | 100万-300万 | 100万-300万 | 30万-100万 |
| **腰部** | 10万-100万 | 10万-100万 | 5万-30万 |
| **中小层** | 1万-10万 | 1万-10万 | 5000-5万 |
| **底层/新人** | <1万 | <1万 | <5000 |

#### F. 企业/个人属性

| 类别 | 说明 |
|------|------|
| **企业势（大箱）** | hololive、にじさんじ、VSPO!、A-SOUL、VirtuaReal 等 |
| **企业势（中小箱）** | 小型社团/公会 |
| **个人势** | 无公司背景、自主运营 |
| **转型** | 企业→个人 或 个人→企业 |

### 1.5 按地域分片去重

一个主播可能出现在多组搜索中（如"绊爱"同时被 JP-01 热门、JP-04 老牌、SP-02 特殊案例搜到），且 VTuber 存在多语种译名问题。如果让一个 agent 一次性读全部 26 个素材文件来做实体去重，上下文过长（>130K）会导致去重质量下降。

**拆分策略**：按 6 个地域分别启动 6 个独立后台 Task，每个 Task 只读取本区 4~6 个素材文件（各 50~80K，完全在上下文窗口内），输出本区去重清单。最后第 7 个 Task 合并 6 个地域清单。

```
Task 指标        Agent 1~6（并行）                    Agent 7（合并）
                 输入：4~6 个素材文件（50~80K）       输入：6 份去重清单（30K）
                 输出：本区去重清单（10~15K）         输出：全球清单（80~120K）
                 耗时：各 2~3 分钟（全并行）          耗时：3~5 分钟
                 并发：6 个同时跑                     串行：待 Agent 1~6 全部完成
```

**Agent 1~6 的 prompt 模板**（以中国大陆区为例）：

```
你负责从 复盘提升词2/整体可行性分析/素材/ 下的大陆区素材文件中提取去重的主播清单。

需读取的文件：
  素材/CN_01_现役热门.md
  素材/CN_02_毕业休眠.md
  素材/CN_03_新人.md
  素材/CN_04_老牌.md
  素材/CN_05_争议倦怠.md
  素材/CN_06_跨类型.md

去重规则：
  - 同名同平台 → 合并信息（各文件的信息可能互补）
  - 同名不同平台 → 分别保留（可能是同主播多平台运营）
  - 日V在B站运营 → 归属"日本"，等合并时处理
  - 信息互补时：取粉丝数最新的、状态最近期的

输出文件：

  每行一个主播。
  然后在文件末尾列出：
  ## 去重说明
  列出所有合并、冲突解决、不确定 case。
```

### 2.1 分析策略

对 Phase 1 筛选出的**每一位主播**，分别启动一个独立的后台 Task（使用 `Task` 工具，`run_in_background: true`），task 内部使用 `streamer-six-dim-review` skill 对该主播进行完整的六维度复盘分析。

**启动方式**：每个 task 的描述为 `分析{主播名}`，prompt 为：

```

主播基本信息：
- 地域：{地域}
- 平台：{平台}
- 所属组织：{企业势/个人势}
- 从业时长：{时长}
- 内容类型：{类型}
- 粉丝规模：{规模}

要求：
1. 严格按照 skill 中定义的工作流执行（搜索→六维评分→关系路径→心之壁→报告）
2. 搜索时必须覆盖主播所属地域的本地语言内容（如日本VTuber必须搜索日文资料）
3. 分析完成后，将完整报告保存到 复盘提升词2/整体可行性分析/reports/{主播名}_六维分析报告.md
4. 报告中必须包含：
   - 基本信息表（地域、平台、组织属性、语言）
   - 六维度评分总览表（每个维度 1-10 分 + 关键发现）
   - 17条关系路径信号表（每条路径的信号强度和发现，标注路径内容）
   - 心之壁判定（厚度 + 风险等级 + 说明 + 是否企业强制厚壁）

   - 地域/文化特殊因子（如跨境消耗、语言障碍、本地平台规则等）

5. 如果某个维度公开信息不足，明确标注"信息不足"而非臆测
6. 报告末尾附加一个"分析可信度自评"：每个维度标注信息充分度（充分/部分/不足）
```

## Phase 3：三级归纳 · 框架评估 · 统计汇总

### 3.0 架构说明

Phase 2 产出约 100 份报告后，受限于 DeepSeek v3 的 128K 上下文窗口，一份报告 ~14K token，无法一次性把所有报告塞给一个 agent 做完整分析。需采用**三级归纳**架构，并在 L0 引入代码预处理绕过 LLM 的算术短板。

```
L0: 代码预处理（非LLM·精确统计）
    从 100 份报告的六维评分总览表和 17 条关系路径信号表中
    提取结构化数值 → 保存为 JSON/CSV
    作用：均值、标准差、频次、检出率、离群值检测（Z-score）
    工具：Python 脚本（按固定格式从 Markdown 表格中抽取）
    
L1: 提取层（20个 agent·并行·每批5~6份报告·128K窗口内）
    读报告 → 输出「结构化分析摘要」
    输出大小：~3K token / 摘要
    
L2: 归纳层（2个 agent·并行）
    Task A：读 L0 数值 + 20份L1摘要 → 02_框架评估报告
    Task B：读 L0 数值 + 20份L1摘要 → 03+04 报告
    两份输入各约 80K，完全在 128K 窗口内
```

**能力边界原则**：

| 能力 | 谁做 | 原因 |
|------|:---:|------|
| 精确统计（均值/std/频次） | 代码 L0 | LLM 算术不可靠 |
| 离群值检测（Z-score） | 代码 L0 | LLM 无法精确跨样本比较 |
| 量表填写（六维评分 + 路径信号 + 心之壁） | LLM ✅ Phase 2 | 定性判断是 LLM 强项 |
| 模式匹配（"哪些案例符合路径⑥沉默？"） | LLM ✅ L2 | 已知模式的跨案例检索 |
| 矛盾信号语义归类（"这个矛盾属于哪类断裂？"） | LLM ✅ L1 + L2 | 需要理解矛盾描述的含义 |
| 发现全新规律 | LLM ⚠️ 降低期望 | 改为"列出与框架预设不符或不匹配的观察"，不要求主动推新因果链 |
| 跨案例交叉关联 | LLM ✅ L1 + L2 | L1 标注"此案例与 L1-07 的 xx 类似"，L2 整合 |

---

### 3.2 L1：提取层（20个 agent·并行）

**触发时机**：L0 完成后立即启动。

**目标**：每个 agent 读 5~6 份报告，生成紧凑的结构化分析摘要。只做**语义提炼**（异常描述、跨案例关联、不匹配框架的现象），不做精确统计。

```
Agent 指标
  每批：5~6 份报告
  输入：报告 5×14K + 指令 5K ≈ 75K（128K窗口安全）
  输出：~3K token 的紧凑摘要
  并发：20 个全并行（互不依赖）
  耗时：各 3~5 分钟
```

**L1 Agent prompt 模板**：

```
你是六维度框架的分析摘要提取器。请读取以下 5 份报告，为每份输出一份紧凑的结构化摘要。

需读取的报告：
  [列出 5 份报告的文件路径]

不要重新评分或重新分析——只从报告中**提取和浓缩**已有内容。

每份报告输出以下内容（YAML-like 紧凑格式）：

```yaml
主播: {名}

评分: 人设{/10}, 互动{/10}, 粉丝{/10}, 营收{/10}, 状态{/10}, 内容{/10}

# --- 路径信号摘要（仅列信号强度≥中或矛盾/断裂的路径）---
路径摘要:
  - ③互动≈内容: {强度}, {一句话关键发现}
  - ⑥状态→人设·前台崩塌: 沉默, {如果沉默，为什么？心之壁厚/企业强制？}
  最多列出 6 条有实质发现的路径

# --- 矛盾信号 ---
矛盾: {列出所有编号矛盾信号，每条一句话}
  - {编号 + 矛盾类型 + 一句话}

# --- 心之壁 ---
心之壁: {类型}, 风险{等级}, {如果是厚壁}企业强制?{是/否}
预警疲劳: {是/否}, {如果是，一句话}

# --- 异常标记 ---
离群候选: {是/否}, {原因：哪个维度偏离同组均值≥2分或疑似异常}
框架未覆盖: {是/否}, {一句话描述报告中明确说了"框架未覆盖此现象"}
地域特异性: {是/否}, {一句话}

# --- 潜在跨案例关联 ---

# --- 信息不足标记 ---
维度信息不足: {列出标注为"不足"的维度，逗号分隔}

```

【重要约束】
1. 使用紧凑格式，每个字段不超过一句话
2. "注"和"与其他报告的关联"是高频价值字段——好好写
3. 框架未覆盖的现象——只记录"报告中明确说了框架没覆盖这个"的，不要自己推断
4. 不做任何算术（均值、频次等），只做语义提取

输出文件：
  复盘提升词2/整体可行性分析/l1_summaries/l1_batch_{批次编号}.yaml
```

**输出文件**：存入新目录 `复盘提升词2/整体可行性分析/l1_summaries/`，共 20 个 yaml 文件。
