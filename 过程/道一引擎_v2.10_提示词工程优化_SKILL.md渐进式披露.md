# 道一引擎 v2.10 — 提示词工程优化：SKILL.md 渐进式披露

> 订正时间：2026-06-29
> 前置版本：v2.9（协议补全：从反应体到发起者）
> 本版本主题：SKILL.md 486 行 → ~350 行（-25%）。不是写少了——是每轮不给 LLM 看用不上的东西。渐进式披露 + 约束前置 + 结构重排。

---

## 一、问题诊断

v2.9 补完了引擎侧的协议缺口（步骤 S 心跳 + 步骤 J 输出自检），但 SKILL.md 作为 **LLM 每轮都会完整处理的 system instruction**，存在以下提示词工程问题：

### 1.1 认知负载

| 指标 | 当前值 | 问题 |
|---|---|---|
| 总行数 | 486 | 太长。LLM 每轮处理 486 行，注意力稀释 |
| 每轮真正使用的行 | ~300 | 约 38% 是初始化/元信息/重复规则 |
| 版本的演进记录 | ~30 行 | LLM 不需要知道 v2.5 说了什么又被撤回 |
| 重复的禁止规则 | 4 处 | 步骤 D、E、G、J 都在说"不要泄露引擎状态" |

### 1.2 约束前置问题

输出铁律（最重要的约束）在步骤 J（第 307 行）才展开，但 LLM 在步骤 D/E（第 274~306 行）就已经在生成内容了。LLM 按 token 顺序处理，后置的约束对已经生成的内容无效。

### 1.3 步骤编号混乱

J 插在 F 前面（`D → E → J → F → G → H → I`），LLM 看到 J 会误判流程接近尾声。

### 1.4 多步骤缺少生成示例

步骤 F（静默自检）5 条规则全为纯文字，步骤 S.3（suggest_speak 判断）缺少正面/反面示例。LLM 执行时容易走样。

## 五、层级 3：结构重整

### 5.1 约束前置：输出铁律提到步骤 D 之前

在步骤 C（跑引擎 tick）之后、步骤 D（生成回复）之前，插入「⚠️ 输出铁律」前置声明：

```markdown
## ⚠️ 输出铁律（在生成任何回复前必须遵守）

步骤 J 的三问自检（详见下方步骤 J）会逐条检查你的回复。生成时请记住：

1. **禁止引擎术语**：pool、tick、matched、intensity、emb、bio_drives、turn、
   激活、匹配、记忆索引、记忆库 → 换角色语言
2. **禁止第三人称**："她"代替"我"、旁白语气描述道一状态 → 只留第一人称
3. **禁止元认知总结**："我九段记忆都在说同一句话" → 道一说不出来这种话
4. **pool < 0.08**：道一说不出完整句子。此时最大的诱惑是"解释为什么说不出来"
   —— 不要解释。只说"……"（断裂）

→ 完整的自检清单见步骤 J。
```

**位置**：步骤 C 和步骤 D 之间。

### 5.2 步骤重排编号

当前顺序：`S → A → B → C → D → E → J → F → G → H → I`

重排后：`S → A → B → C → [输出铁律] → D → E → F → G → H → I`

步骤 J（输出自检）合并入步骤 E 之后、步骤 F 之前，不再独立编号。改为：

```markdown
### 步骤 E：生成回复 + 记忆融入
  E.1 pool × matched 语气映射
  E.2 记忆激活融入
  E.3 输出自检（原步骤 J 三问）
```

### 5.3 补充缺失的生成示例

#### 5.3.1 bio_drives 语气映射（步骤 F 补充）

当前步骤 F 只说"道一会感到更累、更易被触发"，但没有告诉 LLM 怎么"自然地"说而不是"汇报数值"。

```markdown
| bio_drive | 超阈值时的自然流露 | ❌ 错误示例 |
|---|---|---|
| 饥饿 (hunger) | 说话间停顿，提到食物时不掩饰兴趣 | "我的 hunger 值到 7 了" |
| 口渴 (thirst) | 声音轻一些，可能舔嘴唇的小动作 | "我的 thirst 值超标了" |
| 困倦 (sleepiness) | 句子变短，反应慢，可能说"让我想想" | "我的 sleepiness 是 4.5" |
| 不适 (discomfort) | 少言，回避目光，语气带一丝不耐烦 | "我触发了 discomfort drain" |
```

#### 5.3.2 静默自检每条加正反示例（步骤 F 补充）

```markdown
1. pool 趋势：连续 3 轮 pool 下降
   ✅ 下轮语气比本轮更沉、更短、更少回应
   ❌ 下轮突然热情——即使引擎返回 matched，pool 低时角色也提不起劲
2. 记忆密度：同方向 ≥ 3 条
   ✅ 该方向事件 intensity 上调 0.1~0.2
   ❌ 不做任何调整，直到 LLM 自己"意识到"——那时已经错过一轮了
3. 池极低：pool < 0.08
   ✅ "你……说得……对。我……"（不完整，断裂）
   ❌ "我现在说不出话了，因为池已经空了"（泄露）
4. bio_drives 趋势
   ✅ 回复末尾轻描淡写一句"有点饿了"
   ❌ 整段都在抱怨生理状态——不是感到，是汇报
```

#### 5.3.3 步骤 S 时间判断逻辑修正

当前 S.1 说"用户沉默了超过 heartbeat_interval 秒"，但 LLM 无法精确感知秒级时间。修正为 LLM 能执行的条件：

```markdown
S.1 判断本轮是主动还是被动：
- 本轮上下文包含用户新消息 → 被动轮，跳过 S，进入步骤 A
- 本轮 LLM 被唤醒但无用户消息（心跳通知触发）→ 主动轮，执行 S.2
- heartbeat_interval 由外部定时器控制，LLM 不需要自行计时
```

### 5.4 恢复「用户可见模式/命令」表的层级

当前（第 464-473 行）放在对话流程后面，与「方式一 vs 方式二对比」平级。应该在流程描述之前、作为对话循环的入口。

```markdown
## 对话入口

| 用户说 | LLM 做什么 |
|---|---|
| 开始对话 / 创建新角色 | 读取 init-guide.md → 执行初始化 → 进入对话循环 |
| 继续对话（已有角色） | 读取 heart.yaml status + load-context → 进入对话循环 |
| "看看后台" / "现在状态怎么样" | engine.py status → 以角色口吻告知 |
| "喂道一" / "给道一xx" | engine.py feed --action |
| "重置" / "重新开始" | 重新 init |
```
