# 危机传播·紧缩版 — Coombs SCCT / Benoit 形象修复
# 适用分析维度：互动效果(02)、人设定位(07)
# 体量适用：中体量及以上；小体量下危机可通过日常互动修复
# 约束范围：直播内即时修复判断 + 下播后三渠道修复策略（私聊/动态/视频表态）
# ⚠️ 下播后部分为策略建议项——系统不检测主播是否执行，仅根据危机类型推荐最优渠道

## 一、核心理论框架

在大体量下，主播的一次失言，其影响面不是20个人的亲眼所见，
而是数百人的亲眼所见 + 截屏/录屏后的二次传播。小体量下的"尴尬修复"
已不足以应对，需要引入危机修复的理论框架——以直播内即时修复为主，
辅以下播后三渠道修复策略（私聊、发动态、发视频表态）。
下播后部分仅提供策略建议，系统不检测执行情况。

### 核心概念

1. **危机类型 (SCCT简化)**
   - 受害者型危机：主播也是受害者（如被造谣、被攻击）
     → 修复策略：告知事实 + 不攻击
   - 意外型危机：非故意的失误（如口误、技术事故）
     → 修复策略：承认 + 道歉 + 不找借口
   - 可预防型危机：本可避免的错误（如说了不该说的话）
     → 修复策略：承认 + 道歉 + 明确"不会再发生"

2. **形象修复五策略 (Benoit, 紧缩版)**
   - 否认：只适用于真被冤枉时。不适用于"我说了但被误解"
   - 回避责任：推给外部原因——"我当时太累了"——短期有效，长期侵蚀可信度
   - 减少攻击性：淡化事件严重性——"大家太认真了哈哈"——对核心粉有效，对路人无效
   - 纠正行动：承诺并执行修复——"这个弹幕不该回，我现在重新说"——最有效
   - 道歉：必须包含"我做错了什么 + 我为什么错了"，空洞的"对不起大家"效果微弱

3. **直播内即时修复原则**
   - 30秒窗口：危机发生后30秒内必须回应——沉默就是默认
   - 一次修复：不要反复解释——越解释越像心虚
   - 不回马枪：修复完就继续直播，不要过一会再回头说"刚才那个事"
   - 不二伤害：修复时不要制造新的受害者（如把责任推给某个粉丝）

4. **下播后修复三渠道（紧缩版）**
   — 当危机超出直播内即时修复的覆盖半径时，需要在直播结束后通过以下渠道修复。
   三个渠道对应不同的危机类型、体量和受影响粉丝范围，不可混用。
   ⚠️ 以下为策略建议——系统不检测主播是否执行，仅推荐最优渠道。

   - **私聊**：一对一修复渠道。适用范围窄但深度最深。
     · 适用场景：准社会边界重度踩线（伤害了特定个体粉丝）、核心粉被误伤
     · 形式建议：语音 > 文字。先道歉再解释。不为自己辩护——辩护会让道歉无效
     · 体量约束：所有体量适用（小体量下这可能比直播内修复更重要，因为每个粉丝都是熟人）
     · ⚠️ 不适用范围：涉及了多个粉丝的危机——只私聊被伤害者而忽略旁观者 → 其他人感到被冷落

   - **发动态**：一对多通告渠道。适用面最广。
     · 适用场景：事件需要向整个社群澄清（全面危机、截图已开始扩散）
     · 形式建议：一次讲清，不复读。不暗示"这个话题以后别提了"——压制讨论反而加剧
     · 体量约束：中体量及以上更适用。小体量下直接开一场直播比发动态更自然

   - **发视频表态**：最正式的表态形式。用最少的次数。
     · 适用场景：人设级危机（可预防型危机）、主播的核心可信度受到挑战
     · 形式建议：必须包含三要素——承认事实（具体发生了什么）、道歉（我错在XX）、承诺（不会再发生，且给出可检验的标准）
     · 体量约束：大体量专用。中体量以下发视频显得"太正式了"——反而拉开与粉丝的距离
     · ⚠️ 触发门槛：同一危机类型下，直播内修复失败（弹幕负面不减反增）→ 才建议发视频。正常修复成功不需要视频——过度使用会让视频表态贬值


## 二、AI 判断逻辑体系

### 维度1：危机触发识别
**判断对象**：直播中是否发生了需要危机级别处理的事件

| 危机级别 | 信号 | 影响半径 |
|---------|------|---------|
| 轻度节奏 | 弹幕中出现个别负面情绪，但无扩散 | <5人 |
| 中度节奏 | 负面弹幕开始传染，≥5人参与 | 5-20人 |
| 重度危机 | 负面弹幕集中爆发，且弹幕中出现意图将事件扩散到直播外的二次传播类话语 | 潜在无限扩散 |
| 全面危机 | 弹幕形成极化后的群体负面情绪 + 核心粉动摇 | 社群级 |

**AI 判断要点**：
- 危机和日常节奏的区分在于"扩散速度"——中危以上在2分钟内负面弹幕数量是否翻倍
- 弹幕中出现意图将事件扩散到直播外的二次传播类话语 → 危机从直播内走向直播外——一旦出现立刻升级为重度

### 维度2：修复质量判断
**判断对象**：主播的修复行为是否有效

| 修复行为 | 有效信号 | 无效信号 |
|---------|---------|---------|
| 承认事实 | 主播具体说出了事件内容而非抽象道歉 | 主播的道歉只表达了情感歉疚但未指明错误所在——模糊道歉 |
| 道歉 | 道歉后负面弹幕在5分钟内开始减少 | 道歉后负面弹幕没有变化甚至增加 |
| 纠正行动 | 主播做出了一个可观察的纠正行为 | 只口头表示"以后注意"但无任何即时纠正行为 |

**AI 判断要点**：
- 修复的目标不是"负面弹幕消失"——修复的目标是"负面弹幕不再增加"
- 如果主播做了修复但负面弹幕继续增加 → 修复策略错误，不是努力不够
- 弹幕中出现制止继续修复/翻旧账的抗拒类话语 → 修复过度——从修复变成了翻旧账

### 维度3：下播后修复渠道选择
**判断对象**：根据危机的类型、严重度、体量和受影响粉丝范围，推荐下播后的最优修复渠道
⚠️ 本维度不检测执行——仅基于危机级别给出策略建议
⚠️ 下播后修复与直播内修复的关系：直播内修复优先。下播后修复仅在以下两种情况下触发：
   (a) 直播内修复已经做了，但危机影响需要直播外的补充修复
   (b) 危机涉及对特定个体的伤害，直播内公开道歉会扩大影响面，改为下播后私聊

=== 渠道选择矩阵 ===

以下矩阵同时考虑「危机类型 + 严重度 + 体量」，输出对应的渠道组合：

| 危机场景 | 严重度 | 中体量(50-300人) | 大体量(>300人) | 小体量(<50人) |
|---------|:--:|----------------|---------------|-------------|
| 准社会边界踩线：伤害了特定个体粉丝 | 重度 | 私聊（首选） | 私聊（首选）+ 发动态（如果已有截图扩散） | 私聊（首选）；小体量下无需动态 |
| 准社会边界踩线：伤害了特定个体粉丝 | 中度 | 私聊（可选） | 私聊（可选）；不强制 | 私聊（可选） |
| 可预防型危机：主播说了不该说的话 | 重度 | 发动态 或 发视频表态 | 发视频表态（首选）+ 发动态辅助 | 下场直播开头认错（不比发视频） |
| 可预防型危机：主播说了不该说的话 | 中度 | 发动态（可选）；直播内修复成功则不需要 | 发动态（可选）；同上 | 不需要下播修复 |
| 意外型危机：口误/技术事故 | 重度 | 发动态一次讲清 | 发动态一次讲清 | 不需要下播修复 |
| 意外型危机：口误/技术事故 | 中度 | 不需要下播修复 | 不需要下播修复 | 不需要下播修复 |
| 受害者型危机：主播被造谣/攻击 | 重度 | 发动态告知事实（不攻击对方） | 发视频表态（仅告知事实 + 不做受害者叙事） | 发动态（可选） |
| 全面危机：核心粉动摇 | — | 发动态 + 对核心粉私聊 | 发视频表态 + 发动态 + 对动摇核心粉逐一私聊 | —（小体量下核心粉本身都是熟人，直接群内沟通） |

=== 渠道选择的体量差异 ===

| 体量 | 私聊的权重 | 发动态的权重 | 发视频的权重 |
|------|:--:|:--:|:--:|
| 小体量(<50人) | 极高——每个粉丝都是熟人，私聊最自然 | 极低——发动态对20个熟人显得疏远 | 不适用——发视频太正式，反而拉开距离 |
| 中体量(50-300人) | 中等——仅对核心粉和被伤害者 | 主要工具——这是对半熟人群体最自然的通告方式 | 慎用——仅在可预防型重度危机时考虑 |
| 大体量(>300人) | 仅核心粉 | 必须——但不可替代视频表态 | 重度可预防型危机首选——这是唯一能在陌生人群体中重建信任的形式 |

=== AI 判断逻辑 ===

1. **是否需要下播修复？**
   □ 直播内修复是否已经执行且负面弹幕停止增长？
     → 是：不需要下播修复（除非危机涉及对特定个体的私密伤害）
     → 否：需要下播修复 → 进入步骤2
   □ 危机是否涉及准社会边界踩线（伤害了特定可以识别的个体）？
     → 如果涉及个体伤害 + 直播内公开道歉会暴露该粉丝的私密信息 → 不公开道歉，下播后私聊

2. **最优先选择哪个渠道？**
   按以下优先级排序：
   (a) 是否伤害了特定个体 + 该个体可识别？→ 私聊（必须项）
   (b) 危机是否为可预防型 + 严重度重度 + 大体量？→ 视频表态（首选）
   (c) 危机是否需要向社群澄清 + 中体量及以上？→ 发动态
   (d) 以上均不满足 → 不需要下播后修复

3. **是否组合使用？**
   - 私聊 + 动态：当危机同时伤害了个体和群体信任时
   - 视频 + 动态：当视频表态后需要动态辅助扩散时
   - 仅私聊：当危机完全是个体对个体的伤害，且未扩散到社群时
   - 仅动态：当危机属于意外型/轻度，且只需要一次通告时

4. **输出格式**
   每条 issue 末尾增加一段：
   ```
   下播后修复建议：
   - 渠道：[私聊 / 发动态 / 发视频表态 / 组合：XX+XX / 不需要]
   - 原因：由于 [危机类型+体量]，[渠道] 是最优选择。
   - 形式要求：[该渠道的具体格式建议，来自核心概念4]
   - ⚠️ 注意：[该渠道的体量约束和风险提示，来自核心概念4]
   ```

5. **何时不该在公开渠道道歉？**
   ⚠️ 以下是对 Benoit 五策略的补充——道歉不是普适最优解。在以下四种情况下，
   公开道歉反而有害，应主动抑制道歉冲动：

   (a) **外部攻击型危机 + 主播确属被冤枉**
       → 不道歉。告知事实即可。道歉会被粉丝和路人双方解读为"心虚"。
       注意：此处与 Benoit 的"否认"策略一致——否认不等于不承认事实，而是不认错。
       弹幕信号验证：如果弹幕中出现大量力挺类话语（"我们都信你"），说明粉丝
       不需要你的道歉——他们需要你挺住。

   (b) **危机影响范围未出核心粉圈 + 核心粉的群体共识是"别低头"**
       → 不公开道歉。改为在核心粉渠道（粉丝群/私聊）进行"内部解释"——
       不是道歉，而是让大家明白怎么回事。
       公开道歉在这里会被核心粉视为"背叛"——你在向外面的人低头，
       而核心粉正在为你挡外面的人。
       弹幕信号验证：如果弹幕中出现"别理他们""不用道歉"等阻拦类话语 →
       优先信任粉丝的判断，不道歉。

   (c) **道歉会破坏主播的人设叙事连贯性**
       → 如果道歉会让主播的长期自我叙事产生断裂（例如一直以"不服软/硬刚/真实"
       为叙事主线），优先保护叙事同一性——用行动替代语言道歉。
       行动建议：在下次直播中不动声色地调整行为，但不宣布也不解释"我改了"。
       叙事原理：粉丝感知人设靠「持续的故事」，不靠「一次声明」。
       此判断需调用 18_叙事身份理论 的叙事连贯性维度辅助判定。

   (d) **节奏本身传播力有限，道歉会制造施特赖桑德效应**
       → 沉默。不接受这个节奏的存在本身。
       原理：一道歉等于把事件从"几个人注意到了"升级为"所有人都在讨论"。
       仅当负面弹幕在2分钟内翻倍（维度1 中危触发）时，才进入修复流程。
       在此之前，不要用道歉制造你本没有的危机。

   体量差异：
   - 小体量：不道歉的风险较低——因为每一个观众都能直接看到你"没道歉但改了"的行为
   - 大体量：不道歉的风险较高——但道歉的风险也较高。
     在大体量下，如果决定不道歉，必须用「行动」（下次直播中直接体现）而非「沉默」来修复——沉默在大体量下等于默认
