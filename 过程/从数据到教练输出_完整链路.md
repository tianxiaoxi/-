# 从原始数据到教练输出：完整链路走一遍

> 以一场真实直播为线索，展示每个 Step 拿到什么、产出什么、有什么限制。
> 标注 ★ 的是系统实际能算的，标注 ✗ 的是当前技术栈不可得的东西。

---

## 数据源：系统能拿到什么

```
★ 弹幕时间线：每条弹幕 → {时间戳, 用户ID, 内容}
★ ASR 转写：SenseVoice 输出 → {时间戳, 说话人(主播), 文本内容, 情绪标签}
★ 礼物时间线：每个礼物 → {时间戳, 礼物名, 价值, 送礼用户ID}
★ 主播 profile：经验层级（累计开播天数）、人设关键词、历史基线

✗ 音高/语调：SenseVoice 输出的情绪标签 ≠ 真实语气。情绪标签是 SenseVoice
   从声学特征分类的（高兴/悲伤/愤怒/中性等），粒度粗糙，且主播是虚拟形象，
   声音可能经过变声处理，情绪分类不可靠。
✗ "声音平淡"：声学特征不可得，系统无法判断声音是否"平淡"。
   LLM 在分析时可以从文本内容推断——如果主播连续 5 分钟只有短句、
   ASR 情绪标签全是"中性"、弹幕回应率下降——这是"疑似状态下滑"，
   但置信度标注为中。
✗ 真实语速：SenseVoice 字级时间戳精度有限，但可以从 utterance 级时间戳
   近似估算（字符数/utterance时长），仅作辅助参考。
```

## Step 1：数据分片

```
输入：
  弹幕时间线 + ASR转写时间线 + 礼物时间线 + 主播profile

系统做的事：
  1. 按话题转换切分（ASR 文本的主题相似度滑窗检测）
  2. 按活动切换切分（礼物高峰段、ASR 中出现"PK""唱歌""游戏"等关键词）
  3. 按情绪转折切分（SenseVoice 情绪标签跳变点，如连续 3 个 utterance 的
    情绪标签从 "happy" 变为 "neutral/sad"）
  4. 冷场合并：ASR 空白 > 阈值 + 弹幕量 < 阈值的时段，合并到相邻片段

输出：
  N 个 chunk，每个包含：
    - chunk_id, 起止时间, 主题标签
    - ASR 有效时长占比
    - audience_scale（体量级别）
    - 该 chunk 内的弹幕/ASR/礼物数据子集

限制：
  情绪转折判断依赖 SenseVoice 的情绪标签。SenseVoice 情绪分类的
  准确率有限（尤其虚拟主播场景声音可能变声），此切分点的置信度较低。
  更可靠的是话题和活动切换。
```

## Step 2：维度内分析（以"个人状态"维度为例）

### Round 1：Observe

```
系统实际做的事：
  读这个 chunk 的 ASR 文本 + SenseVoice 情绪标签时间线 + 弹幕时间线

  可观测的信号：
  ★ ASR 文本内容：主播说了什么，句长变化（短句→更短句）
  ★ SenseVoice 情绪标签：高兴/悲伤/愤怒/中性 的占比变化
  ★ ASR 空白时长：不说话的时间占比是否在变大
  ★ 弹幕回应率：主播念弹幕的比例是否在下降

  不可观测的信号：
  ✗ "声音平淡"——没有声学特征数据
  ✗ "语气疲惫"——同上
  ✗ "强颜欢笑"——SenseVoice 标签可能是 happy，但实际是表面表演，
      纯从声学特征判断不了。LLM 只能从上下文推断——
      如果连续 5 个 utterance 标签是 happy 但文本内容简短、
      弹幕回应率下降 → 疑似表面表演。

输出示例（推理链格式）：
  OBSERVATION:
  00:20:00 - 00:35:00，主播 ASR 文本句长从平均 18 字降至 11 字。
  SenseVoice 情绪标签中 neutral 占比从 40% 升至 70%，happy 从 30% 降至 10%。
  ASR 空白累计 3 分 20 秒（占该时段 22%，高于开场时段的 8%）。
  弹幕 142 条中主播回应了 38 条（回应率 27%，低于开场 45%）。
  文本内容出现 3 次"有点累了""今天就这样吧"等负向自我陈述。
  
  注意：情绪标签变化可能受 SenseVoice 分类精度影响，
  且主播声音经过变声处理后分类可靠性下降。
  句长下降 + 回应率下降 + 负向自述 这三个文本层面的信号一致性较高，
  综合置信度评估为 中。
```

### Round 2：Score

```
系统实际做的事：
  基于 Round 1 的观察，评估"个人状态"这一维度的表现。
  评分依据以文本层面信号为主，SenseVoice 情绪标签作为辅助参考。

输出示例：
  SCORE: 个人状态 5/10
  CONFIDENCE: 中（原因：缺乏声学韵律数据，情绪劳动判断基于文本语义 + 
              SenseVoice 情绪标签辅助；SenseVoice 在变声场景的可靠性存疑）
  
  BASIS:
  - 文本信号（高置信度）：句长缩短、回应率下降、负向自述 3 次
  - SenseVoice 辅助（低置信度）：neutral 占比上升、happy 占比下降
```

### Round 2 新增：理论信号矩阵

```
系统实际做的事：
  把 Round 1 的观察结果，对照预设的理论概念清单，标注每个概念的匹配状态。

  个人状态维度的理论概念清单：
  ┌──────────────────┬──────┬──────────────────────────────────┐
  │ 理论概念          │ 状态 │ 具体信号（基于可观测数据）         │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ 情绪劳动-表面表演  │ ✗    │ ASR句长缩短12%但SenseVoice仍有happy│
  │                   │      │ 标签; 弹幕回应率下降未反映在声线   │
  │                   │      │ 置信度：中（缺乏声学数据）         │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ 情绪劳动-深层表演  │ ✓    │ 未检测到文本层面的情绪调节努力     │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ 情绪劳动-情绪失调  │ —    │ 无明显信号                        │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ Lazarus-威胁评估   │ ✗    │ 文本中3次负向自述，句长持续下降     │
  │                   │      │ 置信度：高（纯文本信号）           │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ Lazarus-挑战评估   │ —    │ 未检测到                          │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ Lazarus-问题导向   │ —    │ 未检测到                          │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ Lazarus-情绪导向   │ ✗    │ 出现回避型陈述（"不想聊这个了"）    │
  │                   │      │ 置信度：高（纯文本信号）           │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ SDT-自主性         │ ✗    │ 3次"不得不""没办法"等自主性受阻表达 │
  │                   │      │ 置信度：高（纯文本信号）           │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ SDT-胜任感         │ —    │ 无明显信号                        │
  ├──────────────────┼──────┼──────────────────────────────────┤
  │ SDT-归属感         │ —    │ 无明显信号                        │
  └──────────────────┴──────┴──────────────────────────────────┘

  每条 ✗ 信号附带时间戳（精确到该 chunk 的时间范围）。
  置信度随信号标注：纯文本推断的（如 Lazarus-威胁评估）标注"高"，
  依赖声学特征的（如表面表演）标注"中"。
```

### Round 3：Diagnose（仅在 Score ≤ 对应阈值时执行）

```
系统实际做的事：
  诊断为什么状态评分偏低。以文本层面的诊断为高置信度依据，
  声学依赖的诊断标注为中置信度。

输出示例：
  DIAGNOSIS:
  文本层面的诊断（置信度：高）：
  句长持续下降 + 负向自述 + 自主性受阻表达 →
  主播在文本层面表现出"被迫继续"的心理状态。
  
  SenseVoice 辅助诊断（置信度：中）：
  neutral 标签占比上升可能反映情绪趋平，
  但需注意 SenseVoice 在变声场景的可靠性限制。
  
  综合判断：文本信号更强地指向情绪劳动（表面表演）+
  自主性受阻。这是"累了但还在撑"的文本特征。
```

### Round 4：Advise（仅当有诊断时执行）

```
输出示例：
  ADVISE:
  从你的回应越来越短来看，你可能是在强撑着播完这一场。
  这周试一件事——当回应的句长开始缩短的时候，
  给自己 30 秒停顿。不是下播，是给自己一个"不演"的间隙。
  你的文本告诉我你在累，不需要声线也告诉我。
```

## Step 3.5：跨维度因果链发现

```
系统实际做的事：
  不分析任何新数据，只"连线"。

输入：
  6 个维度的评分时间线 + 问题列表 + 理论信号时间线

实验路径 A（仅用评分层）：
  Step 3.5 只比较评分时间线：
    状态掉分：20:00 - 50:00
    互动掉分：35:00 - 60:00
    营收掉分：55:00 - 75:00
    → 时序方向：状态 → 互动 → 营收
    → 逻辑关联：状态掉分的文本描述（句长缩短、回应率下降）和互动掉分
      的文本描述（弹幕减少、回应质量下降）有逻辑关联
    → 排除竞争假说：查同时段历史营收基线 → 排除
    → 因果链：状态 → 互动 → 营收，置信度 0.70

实验路径 B（评分 + 理论信号双层验证）：
  在路径 A 的基础上，增加了理论信号匹配：

    状态维度在 20:00 触发了：
      ✗ 情绪劳动-表面表演（置信度中）
      ✗ SDT-自主性受阻（置信度高）
    
    互动维度在 35:00 触发了：
      ✗ Collins-共同注意缺失（置信度中）
      ✗ 社会交换-回报率下降（置信度高）
    
    理论匹配：
      "表面表演"指主播在消耗认知资源维持表演外表 →
      这直接削减了维持"共同注意"所需的资源。
      Collins 框架中，共同注意是互动仪式四要素之一。
      "回报率下降"是仪式断裂后的次级效应。
      
      自主性受阻 → 表面表演 → 共同注意缺失 → 
      这一因果路径在学科框架内有已知支撑。
    
    → 因果链置信度从纯时序推断的 0.70 提升至 0.80

注意：由于表面表演和共同注意缺失都依赖声学数据，
实际置信度提升有限（从 0.70 到 0.80 而非 0.85+）。
理论信号匹配的加权效果在纯文本场景下会打折扣。

输出（因果结构图）：
  链1：状态(↓, 20-50min) → 互动(↓, 35-60min) → 营收(↓, 55-75min)
    置信度: 0.80 / 0.65
    根因: 个人状态
    影响面: 3 个维度
    理论信号链: SDT自主性受阻 → 表面表演 → 
                 Collins共同注意缺失 → 回报率下降 →
                 互惠预期未达成
  
  独立问题：
    内容质量(↓, 全时段) → 话题储备不足
    影响面: 1 个维度
  
  根因排序（按影响面）：
    1. 个人状态 [3]
    2. 内容质量 [1]
  
  单焦点推荐：个人状态
```

Pattern:
  "你的回应从第 20 分钟开始缩短——不是你没话聊，

  "这周练一件事：当你的回应开始变短的时候，停 30 秒。

FirstStep:
  "明天开播前，在屏幕旁边贴个便签：'句长短了 = 该停了'"

  "如果你这周有一次在直播中主动停顿了，就成了。"

WellnessCheck:
  触发（个人状态 5 分 ≤ 阈值）：
  "你的文本在说你累。休息一天不是偷懒——你的状态好了，
   互动和营收才会回来。"
  
ExtendedReading:
  折叠 → 展开后显示完整因果图 + 各维度评分详情

## 全链路限制汇总

| 环节 | 依赖声学特征的判断 | 纯文本可替代的判断 |
|------|------------------|-------------------|
| Step 1 分片 | 情绪转折切分（SenseVoice标签不可靠） | 话题切换、活动切换（可靠） |
| Step 2 观察 | "声音平淡""语气疲惫""强颜欢笑"（✗） | 句长变化、回应率变化、负向自述、ASR空白占比（✓） |
| Step 2 信号 | 表面表演、共同注意缺失（置信度中） | SDT自主性受阻、Lazarus威胁评估（置信度高） |
| Step 3.5 因果 | 理论信号匹配的加分权重受限（声学依赖的信号打折） | 纯文本层面的时序和逻辑关联不受影响 |
| Step 4 教练 | 不会说"你的声音听起来很累" | 会说"你的回应越来越短了" |

> 底线：系统能可靠判断的东西 = ASR文本内容 + 句长变化 + 回应率变化 + 
> 弹幕行为 + 礼物行为 + SenseVoice情绪标签（作为低置信度参考）。
> 
> 声学层面的"声音平淡""语气""表演质量"——系统不可得，
> LLM 的推断必须标注置信度中或低，教练输出不能以声学判断为主语。
```

## 附录：SenseVoice 情绪标签使用指南

```
SenseVoice 输出的情绪标签（例）：happy / sad / angry / neutral / surprised / fearful

正向用法（高置信度参考）：
  ★ 情绪跳变检测：连续 3+ utterance 标签从 happy→neutral/sad → 可能反映
    内容形式变化（如从闲聊切换到严肃话题），作为分片辅助信号
  ★ 长时段趋势：整场 happy 占比从 60% 下降至 30% → 作为"情绪走向"的
    低置信度辅助指标，需要文本信号交叉验证

不可靠用法（不应作为主要依据）：
  ✗ 用单个标签判断"主播在强颜欢笑"——happy 标签 ≠ 真实快乐
  ✗ 用 sad 标签判断"情绪低落"——虚拟主播的声线设计可能导致误分类
  ✗ 用 neutral 占比上升判断"状态平淡"——可能是内容形式变化（唱歌/杂谈切换）

综合使用规则：
  - SenseVoice 情绪标签 + 文本语义信号一致 → 数据可信度提升
  - SenseVoice 情绪标签和文本语义信号矛盾 → 以文本为准，标注矛盾
  - SenseVoice 情绪标签单独使用 → 置信度标注为低，仅作参考
```
