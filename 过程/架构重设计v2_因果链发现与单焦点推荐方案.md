## 一、当前架构的根本问题

当前系统是六个维度各自独立分析，各算各的。问题不是"算得不准"，而是**算完之后没人连线**。

### 1.1 三个根本矛盾

**矛盾一：设计说"渐进式披露"，但每一句话都在违反**

| 文件 | 行数 | 相当于 |
|------|------|--------|
| `02_互动效果分析.txt` | **767 行** | 10× 设计目标 |
| `07_人设定位分析.txt` | **908 行** | 11× 设计目标 |
| `13_综合总结.txt` | **313 行** | 4× 设计目标 |

一个 767 行的 system prompt 里嵌入了角色设定、全部理论框架、全部子维度判断表、
全部评分标准、全部 JSON schema。LLM 的注意力窗口是有限的——你把所有东西都
塞进去了，它就**所有东西都不认真看**。

**矛盾二：系统是"分析机"而不是"教练系统"**

整个 pipeline 的核心产出是 JSON 报告——评分、P0/P1/P2、severity、confidence、sub_scores。
真正的教练从来不给你一个"评分表"，他们会说：

> "你今天有一件事做得特别对，也有一件事可以试试换种方式。想先听哪个？"

当前系统的出口是一份**成绩单**，不是一个**教练对话**。

**矛盾三：维度 Agent 完全隔离，但问题是跨维度的**

一个真实的例子：

> 主播在某段时个人状态很差（06 维度），导致互动冷场（02 维度），
> 互动冷场导致礼物减少（04 维度）。

当前架构下：
- Agent 06 看到"状态低分"，标记一个 issue
- Agent 02 看到"互动低分"，标记另一个 issue
- Agent 04 看到"营收低分"，标记第三个 issue
- 它们**永远不会对话**，永远不会说"状态差→互动差→营收差是因果链，不是三个独立问题"

### 1.2 核心命题

```
旧：六个医生各看一个科室，给你六张化验单。
新：六个医生看完后，一个全科医生把所有化验单放在桌上，
    画了一张因果图，告诉你"其实你只有一个病，
    其他都是这个病引发的"。
    然后跟你说"这个病不是你身体的问题——
    是你一直没意识到你的身体有这个器官"。
```

这就引出了三个核心跃迁：

```
层次1 → 点状纠错：你在这个时间点做错了        → 修复这个时间点
层次2 → 归因到链条：你的这个问题导致了那个问题  → 找到根源
层次3 → 归因到认知：你对这件事的理解方式缺了东西 → 填补认知空白
```

**当前系统能做层次1。本次重构的目标是做到层次3。**

## 二、重构后的完整架构

```
原始直播数据
    │
    ▼
Step 0: Triage（动态维度激活）
    输入：本场统计 + 主播历史基线（最近 5 场的各维度平均分 ± 标准差）
    输出：维度激活矩阵（深度 / 浅度 / 跳过）
    │
    ▼
Step 1: 数据分片
    输出：N 个时间片段（chunk）
    │
    ▼
Step 2: 维度内分析（渐进式调用链）
    深度维度 → Round 1-4（Observe → Score → Diagnose → Advise）
    浅度维度 → 1 次扫描调用
    跳过维度 → 不调用
    格式：推理链（非 JSON）
    ★ 新增输出：理论信号矩阵（每个子维度×每个理论概念的匹配状态）
    │
    ▼
Step 3: 维度内聚合
    各维度汇总跨片段趋势
    产出：每个维度的评分时间线 + 问题列表 + 理论信号时间线
    │
    ▼
Step 3.5: 跨维度因果链发现 ★ 核心新增
    输入：6 份维度时间线 + 问题列表
    任务：
      1. 时序检测——哪个维度先出问题？
      2. 逻辑关联——出问题的内容是否有逻辑相关性？
      3. 因果方向判定——这场直播谁是因谁是果？
      4. 独立问题识别——哪些问题和链条无关？
      5. 影响面计算——每个根因影响了几个维度？
      6. 单焦点推荐——如果只能改一件事，改哪个？
    输出：因果结构图（链 + 独立问题 + 矛盾信号）+ 按影响面排序的根因列表 + 单焦点推荐
    │
    ▼
Step 4: 教练干预包生成
    基于因果链 + 影响面排序，生成三层诊断输出：
      Anchor（锚点）
        → Pattern（模式）
          → Focus（焦点）+ FirstStep + VerifySignal
      + WellnessCheck（条件性）
      + ExtendedReading（可展开）
    │
    ├──→ Step 5: 教练对话入口
    │     Coach-in-the-Loop 引导式对话 + Q&A 自主查询
    │
    └──→ Step 6: 跨场趋势存档
          结构化存储 + 停滞检测 + 倦怠预警
```

## 三、Step 3.5：跨维度因果链发现

这是整套重构的灵魂。它不分析任何新数据，它的全部工作就是**连线**。

### 3.1 输入

```
每个维度提供：
  - 评分时间线（minute-by-minute 或 chunk-by-chunk）
  - 问题列表（每个问题的起止时间、严重度、一句话描述）
  - 理论信号时间线（每个子维度×每个理论概念的 on/off 状态 + 时间戳 + 一句话描述）
    详见 3.1.1 理论信号矩阵
  - 该维度是否被标记为"深度"或"浅度"（影响置信度）
```

### 3.1.1 理论信号矩阵（Step 2 新增输出）

每个维度的 LLM 分析不是只给一个评分——它同时判断了这个片段中哪些理论概念被"触发"了。把这些判断结构化输出，Step 3.5 就能在信号层面而非评分层面做因果推理。

**为什么评分不够：**

```
评分是数字，信号是有语义的。

"状态在第20分钟掉了" → 只知道掉分，不知道为什么掉
"状态在第20分钟触发了 '表面表演' 和 '自主性受阻'" 
  → 知道掉分是因为主播在硬撑、感觉自己的行为不由自己控制
  → 这个信息才能和互动维度的 '共同注意缺失' 做真正的逻辑关联
```

**矩阵格式（以互动效果维度为例，每个 chunk 输出一份）：**

```
┌────────────────────┬──────────────┬──────────────┬──────────────┐
│ 理论概念 / 子维度  │ 弹幕互动质量 │ 杂谈力表现   │ 情绪价值输出 │
├────────────────────┼──────────────┼──────────────┼──────────────┤
│ Collins-共同注意   │ ✗ 缺失       │ ✓ 正常       │ — 不适用     │
│                    │ 弹幕从讨论   │              │              │
│                    │ 转为单向报到 │              │              │
├────────────────────┼──────────────┼──────────────┼──────────────┤
│ Collins-共享情绪   │ ✗ 缺失       │ ✓ 正常       │ ✓ 正常       │
│                    │ 弹幕情绪极性 │              │              │
│                    │ 降至 0.2     │              │              │
├────────────────────┼──────────────┼──────────────┼──────────────┤
│ 社会交换-回报率    │ ✗ 下降       │ ✓ 正常       │ —            │
│                    │ 弹幕量 ↑     │              │              │
│                    │ 但回应质量 ↓ │              │              │
├────────────────────┼──────────────┼──────────────┼──────────────┤
│ 话轮分配           │ ✓ 正常       │ ✓ 正常       │ —            │
├────────────────────┼──────────────┼──────────────┼──────────────┤
│ 群体符号           │ —            │ ✓ 正常       │ —            │
└────────────────────┴──────────────┴──────────────┴──────────────┘

每条信号附带：时间戳（精确到分钟）、状态（✓/✗/—）、一句话描述
```

**各维度的理论概念清单（核心，可随版本扩展）：**

**互动效果：**
- Collins-共同注意、Collins-共享情绪、Collins-同在边界
- 社会交换-主播回报率、社会交换-粉丝投入度
- 话轮分配、群体符号

**粉丝关系：**
- 准社会交往-边界踩线、准社会交往-体量放大效应
- SDT-自主性、SDT-胜任感、SDT-归属感
- 依恋-焦虑维度、依恋-回避维度
- 群体动力学-群体极化、群体动力学-内群体偏好

**流水营收：**
- 社会交换-CL比较水平、社会交换-CLalt替代选择
- 行为经济学-互惠预期、行为经济学-损失厌恶触发
- 消费心理学-感知价值、消费心理学-支付意愿

**内容质量：**
- 注意力-Sweller认知负荷、注意力-Paivio双重编码
- 口语传播-画面化表达、口语传播-信息密度
- 话题吸引力、节奏控制

**个人状态：**
- 情绪劳动-表面表演、情绪劳动-深层表演、情绪劳动-情绪失调
- Lazarus-初级评估（威胁/挑战）、Lazarus-应对策略（问题导向/情绪导向/回避）
- SDT-自主性、SDT-胜任感、SDT-归属感

**人设定位：**
- Goffman-前台一致性、Goffman-表演纪律、Goffman-后台泄露
- Snyder-自我监控（高/低）
- Piaget-图式同化顺应、Piaget-图式弹性（窄/宽）
- McAdams-叙事身份一致性

**信号输出规则：**

```
每个理论概念在每个子维度下标记为三种状态之一：
  ✓ 正常：该概念未被触发或表现符合预期
  ✗ 异常：该概念被触发且表现偏离预期（附带一句话描述 + 时间戳）
  — 不适用：该概念不适用于当前子维度

只在 ✗ 状态时才附带详细描述。
每个 chunk 全量输出，不需跨 chunk 去重。
```

**聚合时的时间线构建：**

```
Step 3 聚合时，把同一维度所有 chunk 的理论信号拼成时间线：

个人状态维度 理论信号时间线：
  20:00  ✗ 情绪劳动-表面表演（声线维持但语速下降）
  20:00  ✗ SDT-自主性（多次提到"不得不"）
  35:00  ✗ Lazarus-威胁评估（语速进一步下降，出现停顿）
  55:00  ✗ 情绪劳动-情绪失调（笑点多次抓不住）

互动效果维度 理论信号时间线：
  35:00  ✗ Collins-共同注意（弹幕从讨论转为单向报到）
  35:00  ✗ 社会交换-回报率（弹幕数↑但回应质量↓）
  55:00  ✗ Collins-共享情绪（弹幕情绪极性降至0.1）
```

### 3.1.2 理论信号如何提升因果链检测

### 3.2 因果链检测

**核心原则：不预设因果方向。每场直播重新判断。**

**基础检测逻辑（评分层面）：**

```
1. 取各维度评分时间线，找"掉分区间"

   状态掉分：20:00 - 35:00
   互动掉分：35:00 - 55:00
   营收掉分：55:00 - 75:00
   → 时序方向：状态 → 互动 → 营收

2. 验证逻辑关联

   状态掉分的表现是"声音平淡、回应变短"
   互动掉分的表现是"弹幕减少、回应质量下降"
   → 逻辑上匹配：状态差导致回应短，回应短导致弹幕少

3. 排除竞争假说

   营收掉分是否可以直接用"这个时段本身送礼就少"解释？
   → 检查同时段历史对比（该时段在过去 5 场中的平均营收）
```

**增强检测逻辑（理论信号层面）——利用 3.1.1 的信号矩阵：**

```
评分告诉你"什么时候掉"，
理论信号告诉你"为什么掉"，
两个维度之间的理论信号如果存在学科内的已知因果关系，
置信度直接提升。

例：

状态维度第20分钟触发了：
  ✗ 情绪劳动-表面表演（声线维持但语速下降）
  ✗ SDT-自主性受阻（多次提到"不得不"）

互动维度第35分钟触发了：
  ✗ Collins-共同注意缺失（弹幕从讨论转为单向报到）
  ✗ 社会交换-回报率下降

Step 3.5 的推理：
  "表面表演"指主播在用认知资源维持表演外表，
  这直接消耗了她本应用于"维持共同注意"的资源。
  Collins 框架中，共同注意是互动仪式四要素之一——缺了这个，仪式就断裂。
  "回报率下降"是仪式断裂后的次级效应。
  
  → 两个信号组之间的因果关系在学科框架内已知
  → 因果链 [状态→互动] 置信度从纯时序推断的 0.7 提升至 0.85+

同理：
互动维度第35分钟：✗ Collins-共同注意缺失
粉丝关系维度第55分钟：✗ SDT-归属感缺失
  → 归属感缺失是共同注意缺失的自然结果（准社会交往理论中已知）
  → 因果链 [互动→粉丝关系] 置信度提升
```

### 3.3 因果链置信度体系

五条判断依据：

- **时序先后**：A 的掉分发生在 B 之前
- **内容相关性**：A 的问题内容和 B 的问题内容有逻辑关联
- **理论信号匹配** ★ 新增：A 触发的理论信号和 B 触发的理论信号在学科框架内是否存在已知因果关系
- **排除竞争假说**：是否考虑了"第三个因素同时导致 A 和 B"的可能性
- **跨场一致性**（可选）：该因果模式是否在多场直播中复现

置信度阈值与降级规则：

| 置信度 | 结果 | 处理方式 |
|--------|------|---------|
| ≥ 0.8 | 确认因果链 | 参与优先级调整，教练输出中明确呈现 |
| 0.5-0.8 | 可能关联 | 标记为"值得注意的模式"，不参与优先级调整 |
| < 0.5 | 共变观察 | 不输出因果链，仅记录"维度 A 和 B 本场均偏低，但因果关系不明确" |

因果方向无法确定时的处理：

```
当两个维度同步下跌且无法判断因果方向时：
  → 输出标记为 causal_direction: "undetermined"
  → 放入"共变观察"列表
  → 教练语言中表述为"这两个维度都出现了波动——可能有关联，
    但这次我不确定哪个是根"
```

### 3.4 因果方向不固定的处理

因果方向每场都可能不同。系统不做预设判决：

```
这场：状态 → 互动 → 营收
下场：人设偏移 → 老粉沉默 → 场子冷（营收无问题）
再下场：内容质量差 + 营收差 → 两个独立问题，无因果链
继续：互动 ↑ 但营收 ↓ → 矛盾信号，说明转化环节断裂
```

### 3.5 矛盾信号检测

两个维度的评分方向相反时，本身就是一个重要发现：

```
例1：互动 ↑↑，营收 ↓↓
  → 互动好了但礼物少了。
  → 矛盾信号：互动质量和礼物转化之间还有一个环节没通。

例2：状态 ↓↓，人设 →→
  → 状态很差但人设没崩。
  → 正向发现：主播有较强的表演纪律。

矛盾信号默认不在首屏展示（避免困惑），
但保留在扩展阅读和对话素材中供主播主动探索。
```

### 3.6 影响面计算与单焦点推荐

**根因可以有多个。不假设只有一个"核心驱动维度"。**

因果链的根节点 + 独立问题 = 全部根因。每条链的根节点是"因"，链末端的节点是"果"。改因，果自然回升。改果，因还在。

**影响面计算：**

每个根因的影响面 = 它直接或通过因果链间接覆盖的维度数。

```
例：
  链1：状态 → 互动 → 营收
    → 根因"状态"的影响面 = 3（自身 + 互动 + 营收）

  独立：内容质量 ↓
    → 根因"内容质量"的影响面 = 1（仅自身）
```

**单焦点推荐规则：**

```
Step 3.5 的输出列出所有根因，按影响面从大到小排序。

Step 4 教练干预包只推排第一的那个（单焦点）。
其余根因保留在扩展阅读中，标注"下次关注"。

理由：主播一次只能练一件事。
      改影响面最大的那个，效果最明显，主播最能感受到正反馈。
```

**特殊情况处理：**

```
如果只有独立问题（无因果链）：
  → 按评分从低到高排序，推评分最低的那个

如果因果链有多个根节点（一个维度被多个因驱动）：
  互动差 ← 状态差
         ← 人设偏移
  → 两个根因（状态、人设），各自算影响面
  → 影响面相同时，选置信度更高的那条链的根因

如果一条因果链的根节点不止一个（联合根因）：
  状态差 + 内容差 → 互动差
  → 标注为"联合根因"
  → 如果分不开，选置信度更高的

如果影响面相同且置信度也相同：
  → 选评分更低的那个（更紧急）
```

### 3.7 输出格式

```markdown
## 本场因果结构

### 因果链
链1：状态(↓, 20-35min) → 互动(↓, 35-55min) → 营收(↓, 55-75min)
  置信度: 0.85 / 0.70
  逻辑: 状态下滑 → 回应变短 → 弹幕活跃度下降 → 礼物减少
  根因: 个人状态
  影响面: 3 个维度（自身 + 互动 + 营收）

### 独立问题（与任何链无关）
内容质量(↓, 全时段) → 话题储备不足
  影响面: 1 个维度（仅自身）

### 矛盾信号
互动 ↑ / 营收 ↓ → 转化环节断裂
状态 ↓ / 人设 → → 主播表演纪律强（正向信号）

---

### 根因排序（按影响面从大到小）

1. 个人状态 [影响面 3] —— 链1根节点
2. 内容质量 [影响面 1] —— 独立问题

---

### 本期单焦点推荐
**个人状态**
理由：影响面最大——改状态，互动和营收自然会回升。
如果状态恢复后内容质量仍偏低，下周关注内容储备。
```

## 四、教练输出

教练输出不是"给九个章节的报告"，而是三层递进的诊断：

### 层次1：锚点（Anchor）——点状纠错

让主播连接自己的体验。不说"你做错了"，说"你感觉到了吗"。

```
"今天直播第三段的时候，弹幕突然少了——你当时有感觉吗？"
```

### 层次2：模式（Pattern）——归因到链条

让主播看到重复行为模式。从"单次话说错"升级为"可复现的模式"。

```
"你每次聊完复杂话题后都有 2-3 分钟的断档——
 这是大脑在切换频道，不是你没话聊。"
```

### 层次3：焦点（Focus）——归因到可改的根

让主播知道改哪一件事效果最大。从"这里有问题"升级为"改这里，其他自然会好"。

```
"你这周练一件事：在感觉到累的第一个信号出现时，
 给自己一个 30 秒的停顿。改状态，互动和营收自然会回升。"
```

### 三层递进的使用规则

```
因果链清楚 → 走到 Layer 3（焦点：改根节点，影响面最大）
只有独立问题 → 停在 Layer 2（模式：重复行为特征）
没有可辨识的模式 → 停在 Layer 1（锚点：只提醒，不归因）
```

### 教练干预包完整结构

```
1. Anchor（锚点）：一句主播自己能感受到的话
2. Pattern（模式）：一个主播可能没有意识到的重复行为
3. Focus（焦点）：一个本期可以练习的具体技能
4. FirstStep（第一步）：30 秒内可以做的事
5. VerifySignal（验证信号）：主播怎么知道自己做对了
6. WellnessCheck（休息提醒）：仅在个人状态得分偏低时出现
7. ExtendedReading（扩展阅读）：可展开的深度分析，默认折叠
```

## 五、渐进式调用链（维度内）

每个深度维度内采用 4 轮渐进式调用，替代当前的 1 次巨型 prompt 调用。

### Round 1: Observe（观察）

```
system_prompt: "你是一个虚拟主播互动观察员。你的任务只有一件：
               识别这段时间里主播和观众之间实际发生了什么。
               不要评分，不要给建议，不要引用理论。
               输出：时间线叙事 + 关键互动事件列表。"
```

### Round 2: Score（评分，仅在 Round 1 产出"有值得分析的事件"时执行）

```
system_prompt: "你是一个互动质量评估员。基于上一轮的观察，
               给这个片段打分。只打分，不给建议。
               评分时参考以下标准：[60行评分细则]
               输出：评分 + 评分依据。"
```

### Round 3: Diagnose（诊断，仅在 Round 2 评分 ≤ 7 时执行）

```
system_prompt: "你是一个互动问题诊断员。基于前两轮结果，
               找出这个片段中互动问题背后的原因。
               可以查阅以下理论：[理论文件按需加载]
               输出：诊断 + 理论依据。"
```

### Round 4: Advise（建议，仅在 Round 3 产出了诊断时执行）

```
system_prompt: "你是一个教练。基于前三轮结果，
               给出一个具体的、可执行的改进建议。
               只给一条建议。给主播能照着做的话术。"
```

### 条件执行机制

| 条件 | 执行的 Round |
|------|------------|
| Round 1 发现"无值得分析的事件"（如纯唱歌） | 后续全部跳过 |
| Round 2 评分 > 7 | 跳过 Round 3、Round 4 |
| Round 3 未产出诊断 | 跳过 Round 4 |

### 理论按需加载

每个理论提供两个版本：
- **精要版**（40-60 行）：默认在 Round 3 加载
- **完整版**（200+ 行）：仅在现象与已有框架不匹配时加载

### 维度→理论映射

| 维度 | 核心理论 |
|------|---------|
| 互动效果 | 互动仪式链 (Collins) + 社会交换 (Thibaut & Kelley) |
| 粉丝关系 | 准社会交往 (Horton & Wohl) + 自我决定理论 (Deci & Ryan) + 依恋理论 (Bartholomew) |
| 流水营收 | 社会交换 + 行为经济学 + 消费心理学 |
| 内容质量 | 注意力心理学 + 口语文化理论 (Ong) |
| 个人状态 | 情绪劳动 (Hochschild) + Lazarus 压力模型 + SDT |
| 人设定位 | 印象管理 (Goffman) + 自我监控 (Snyder) + 认知图式 (Piaget) |

### 为什么渐进式调用链放最后实施

改动 1（渐进式调用链）是 7 项改动中影响面最大的：
- 需要重写 6 个分片分析文件的 prompt
- 需要重写 Worker 调用逻辑（4 轮调用替代 1 轮）
- 增加了调用次数和延迟

但它也是效果最根本的——如果分析质量不高（prompt 太长导致注意力稀释），
下游再好的推理也弥补不了上游的噪声。

建议策略：前两项（因果链 + 教练输出）先落地验证 → 
用验证期间的实战数据评估当前 prompt 的输出质量 → 
根据数据决定是否启动渐进式调用链。

## 六、动态维度激活 Triage

每场直播不需要 6 个维度全部深度分析。

### Step 0: Triage

```
输入：整场直播的汇总统计（总时长、总弹幕量、总礼物价值、
      主播ASR情绪摘要）
      + 主播历史基线（最近 5 场的各维度平均分 ± 标准差）

任务：
  1. 快速扫描：有没有维度明显不需要深度分析？
     判断标准：
     - 本场数据 vs 历史基线：在基线 ±1 SD 以内 → 浅度扫描
     - 上一场某个维度有 P0 标记 → 本场该维度强制深度

  2. 输出：维度激活矩阵
     {
       "互动效果": "深度",
       "粉丝关系": "深度",   ← 上一场有粉丝流失信号，继续深度
       "流水营收": "浅度",   ← 连续 4 场稳定，扫一眼就行
       "内容质量": "深度",
       "个人状态": "深度",   ← 上一场已经偏低，必须深度
       "人设定位": "浅度"    ← 最近没什么变化
     }
```

### 三个激活级别

| 级别 | LLM 调用 | Prompt 大小 | 做什么 |
|------|---------|-------------|--------|
| **跳过** | 0 次 | — | 历史 5 场评分稳定，本场无明显异常，不分析 |
| **浅度扫描** | 1 次 | ~100 行 | 只判断"有没有明显问题"，不产出子维度评分 |
| **深度分析** | 4 轮 | 渐进式 | 完整的 Observe → Score → Diagnose → Advise 链 |

### 底线保护

个人状态维度不做浅度/跳过——除非连续 10 场评分 ≥ 8 且波动 < 0.5，否则始终"深度"。
主播的健康不是可以跳过的事。

### 新主播冷启动

- 前 5 场强制全维度深度分析，积累基线数据
- 3-4 场基线时只允许"深度→浅度"降级，不允许"深度→跳过"
- 5 场后自动启用完整的 Triage 激活逻辑

### 全维度跳过时的边界行为

系统输出一个极简版教练干预包：
- 正向确认："本场所有维度持续稳定，暂无特别关注项。保持当前节奏。"
- 扩展阅读入口（主播可主动查看历史趋势）
- 教练对话入口正常开放

## 七、推理链替代 JSON Schema

中间步骤（Step 2-3.5）全部使用推理链格式。

### 为什么

```
JSON 格式的问题：
  - LLM 花 tokens 在格式化上，而非洞察上
  - 格式正确但内容空洞的输出可能被接受
  - auto-fix retry 消耗额外的 token 成本
  - LLM 的思维是线性的（chain of thought），在嵌套 JSON 中强行打断

推理链的好处：
  - LLM 的思维是线性的 → 推理链匹配它的 native 思维模式
  - 不需要 Pydantic schema 校验 → 不会因格式问题触发 retry
  - 终端不需要解析 → 可以直接展示，也可以被下游 LLM 节点消费
```

### 推理链格式示例

```
OBSERVATION:
在 00:12:30 - 00:15:00 期间，主播连续念了 8 条弹幕但没有在任何一条上展开。
弹幕从第 2 分钟开始从"讨论"变成"单向报到"（"来了""打卡"占比从 15% 升到 40%）。
这是"假热闹"信号。

SCORE: 互动质量 6/10

WHY: 减分不是因为主播没互动——她读了弹幕。减分是因为互动停留在"回应"层，
没有进入"延伸"层。弹幕有来，但没回。

ROOT_CAUSE: 这 8 条弹幕的内容彼此不相关，主播试图照顾每一条但没能串成一条线。

SUGGEST: 下次遇到多条不相关弹幕时，选一条最有"故事性"的展开，
其他弹幕用一句话带过（"XX 说今天吃了火锅——羡慕啊！话说..."）。

IMPACT_ESTIMATE: 如果做到，这个片段的互动评分预计提升 1-1.5 分。
DIFFICULTY: 中等——需要练习"选弹幕"的眼力。
FIRST_STEP: 明天开播时，给自己加一条规则——每条弹幕只做两种处理：
要么一句话微笑带过，要么选一条展开讲 1 分钟。不要有"念完就走"的中间态。
```

### JSON 保留的时机

只在 Step 4（教练干预包）产出结构化数据，用于 Step 6 跨场趋势对比。
只需要保留：session_score、dimension_scores、focus_skill、next_step。

## 八、教练对话接口

在 Step 4 产出教练干预包后，进入**教练对话界面**，而非输出一份报告文件。

### 对话示例

```
系统：今天的复盘跑完了。有一个发现可能跟你有关系——直播第 40 分钟左右的时候，
      弹幕突然少了。你当时有感觉到什么不一样吗？

主播：我觉得自己那时候有点没话说了...

系统：对，我能看到你确实有 2 分钟没什么话。这个情况在过去 3 场直播里都出现了。
      要不要一起看看这三场里"没话说"之前的共同点是什么？

主播：好。

系统：注意到前两次没话说的时候，你刚聊完一个需要"动脑子"的话题。
      这周试试：下次聊完复杂话题，直接在最后问观众一个选择题。
      比如"好了攻略讲完了——接下来想听我唱歌的扣1，想听我讲故事的扣2"。
      这个提问给你 10 秒缓冲，也给观众一个明确的"现在换台了"的信号。
      想试试吗？

主播：好的我试试！

系统：给你总结一下练习卡片：
      - 焦点：复杂话题到闲聊的"桥接"
      - 第一步：聊完硬核内容后，用一个二选一问题过渡
      - 验证信号：提问后 10 秒内 5 人回应
      - 下次复盘时，我会重点看你的"话题切换"环节
      加油！
```

### 对话特性

1. **异步对话**：主播什么时候想"找教练聊聊昨天的直播"就什么时候打开
2. **有状态**：对话可以中断再继续（LangGraph checkpoint 支持）
3. **引导式**：教练多用提问少用陈述——让主播自己发现规律
4. **结束即产出**：对话结束 → 自动生成练习任务卡片 + 验证信号列表

### 与 Q&A 的关系

- 教练对话：复盘后的引导式对话（深度交互，一次一个话题）
- Q&A：主播自主提问（广度查询，想看什么自己问）
- 两者共享 Step 6 的跨场趋势数据，Q&A 可以引用当前教练对话上下文

## 九、完整流程速查

```
Step 0: Triage
  → 本场只有 3 个维度需要深度分析，2 个浅度扫描，1 个跳过

Step 1: 数据分片
  → 产出 12 个时间片段

Step 2: 维度内分析
  → 3 个深度维度各自跑 4 轮渐进调用
  → 2 个浅度维度各跑 1 次扫描
  → 产出：5 份维度时间线（格式：推理链）
  → 附带：理论信号矩阵（每个 chunk 的子维度×理论概念匹配状态）

Step 3: 维度内聚合
  → 各维度汇总跨片段趋势
  → 产出：评分时间线 + 问题列表 + 理论信号时间线

Step 3.5: 因果链发现
  → 评分层面：状态掉分 20min → 互动掉分 35min → 营收掉分 55min
  → 信号层面：状态触发表面表演+自主性受阻 →
              互动触发共同注意缺失 →
              营收触发互惠预期未达成
    （信号间因果关系在 Collins 框架内已知，置信度提升）
  → 独立问题：内容质量独立偏低 [影响面 1]
  → 根因排序：1. 个人状态 [影响面 3]  2. 内容质量 [影响面 1]
  → 单焦点推荐：个人状态（影响面最大，且理论信号支撑最强）

Step 4: 教练干预包
  → Anchor: "你今天直播后半段是不是觉得有点撑不住了？"
  → Pattern: "你的回应从第 35 分钟开始变短了，
              这和上周四的状态下滑模式很像。"
  → Focus: "这周关注一件事——在感觉到累的第一个信号出现时，
            给自己一个 30 秒的深呼吸停顿。"
  → FirstStep: "明天开播前，在桌子上放一张便签：
              '累了就停 30 秒，不是偷懒，是续命。'"
  → VerifySignal: "如果你这周有一次在直播中停下来深呼吸了，
                  那就成功了第一步。"

Step 5: 教练对话入口
  → 主播可以就"我是怎么累的"展开进一步对话

Step 6: 跨场趋势存档
  → 记录本场因果链 + 练习卡片 + 各维度评分
```

### v2 的核心跃迁

```

v2 问：如果因果链不止一条，如果还有独立问题——怎么决定先改什么？
    → 影响面计算 + 单焦点推荐
    
v2 问：怎么让因果推断更可靠？
```

### v2 砍掉了什么（与 v2 初稿相比）

```
砍掉了 Step 3.6 认知归因层。
理由：
  - 因果链本身就是在教认知。主播看五次"状态→互动→营收"后自然就懂了。
  - 原则是给人看的教学框架，不需要系统在输出中翻译成"你这是原则几"。
  - 跨场模式识别（Step 6）可以在主播反复踩同一个坑时做提醒，
    不需要一个单独的"翻译成原则"步骤。
```

## 十一、实施优先级

### 第一波：核心能力（小改动，大效果）

**Step 3.5 跨维度因果链发现 + 影响面计算 + 单焦点推荐**

- 不改任何现有 prompt 文件
- 在 Step 3 和 Step 4 之间插入一个推理节点
- 输入：各维度评分时间线 + 问题列表（初版仅用评分层面）
- 输出：因果结构图 + 按影响面排序的根因列表 + 单焦点推荐

**效果**：主播收到的建议从"你这个问题很严重"变成"你这个问题是另一个问题的根——改这里，其他自然会好"

### 第一波增强（可选，中等改动）

**理论信号矩阵**

- 修改 Step 2 各维度的 Round 2/3 prompt，增加理论信号输出格式
- 为每个维度预配置理论概念清单（见 3.1.1）
- Step 3.5 启用评分+信号双层因果验证

**效果**：因果链置信度从纯时序推断提升至时序+理论逻辑双重验证。

## 附录：写书项目的方法论反向输入

`写书任务/` 下的三层读者结构（萌新/中层/高层）为复盘系统的教练输出设计提供了关键输入。

### 经验层级适配

同一个发现（如"弹幕互动质量低"），对不同层级的主播说不同的话：

**新手（<6 个月）：**
"下次试试把'大家今天想聊什么'换成'今天想听我唱歌的扣1，想聊天的扣2'。
选择题比问答题好用一百倍。"

**成长期（6 个月-2 年）：**
"你注意到了吗——你每次问开放题后弹幕都会变少。不只是问题本身难，
是你的提问时机和话题切换有关。聊完硬核内容后你的大脑需要缓冲。"

**资深期（2 年+）：**
"你的互动已经很好——现在的问题是'热闹但不深'。试一次：
每场只深度回应 1-2 条有故事的弹幕，其他的用一句话带过。"

层级判定基于累计开播天数：新手 < 180 天，成长期 180-730 天，资深期 > 730 天。
层级仅影响教练语言风格和对话引导深度，不影响分析策略。
