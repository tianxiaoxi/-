## 一、已完成的修改

### 1. engine.py — 记忆时间化 + 可述化 + 回忆 + 再巩固

**文件**：`.cursor/skills/daoyi-chat/scripts/engine.py`

| 改动 | 说明 |
|------|------|
| 记忆结构扩展 | 每条 memory 从 `{emb, intensity}` 变为 `{emb, intensity, turn, description}` |
| 旧格式自动迁移 | `_migrate_memories()` 给旧 memory 补上 `turn: 0` 和 `description: ""` |
| `tick` 可带 `--description` | 写入记忆时顺手存一段文本描述（LLM 写的，不是引擎写的） |
| 新增 `recall` 命令 | 用查询向量主动检索相似记忆，**只读**，不消耗 pool |
| 新增 `modify` 命令 | 微调某条记忆的 intensity / emb / description（再巩固） |

#### recall 用法
```bash
python engine.py recall state.yaml '<query_emb>' --k 3
```
返回：每条记忆的 index、description、intensity、similarity、turn。

#### modify 用法
```bash
# 脱敏
python engine.py modify state.yaml 3 --intensity 0.72

# 记忆融合：emb 微调
python engine.py modify state.yaml 5 --emb '[0.22, 0.80, 0.88, 0.55, 0.42]'

# 描述更新
python engine.py modify state.yaml 2 --description "又被想起了一次，和那次很像"
```

> 已验证：`init`、`tick --description`、`recall`、`modify` 全部通过功能测试。

### 2. SKILL.md — 对话流程加入步骤 G（主动回忆）和步骤 H（再巩固）

**文件**：`.cursor/skills/daoyi-chat/SKILL.md`

#### 步骤 G：道一的主动回忆

- 触发条件：沉默转场、新 session 开始、触及敏感方向、用户直接问"你记得那次吗"
- LLM 生成一个**内部事件描述**（道一自己想到了什么），抽取 5 维 emb
- 调用 `recall` 命令检索（只读，不消耗 pool）
- 相似度 > 0.7 且 intensity > 0.5 → 在回复中自然带出
- 禁止暴露引擎术语（"我查了记忆库"、"索引 3 的相似度 0.82"）

#### 步骤 H：记忆再巩固

五种再巩固规则：

| 激活情况 | 记忆变化 | 幅度 |
|---------|---------|------|
| 创伤连续 ≥ 3 轮被 matched，pool > 0.4 | 脱敏：intensity ↓ | 0.02~0.05 |
| 创伤被激活时 pool < 0.2 | 加固：intensity ↑ | 0.02~0.05 |
| ≥ 3 条相似记忆同时激活 | 融合：emb 互相靠拢 | 0.02~0.05 |
| description 与当前事件有新的文本关联 | 描述更新 | — |
| 未被激活 > 20 轮 | 自然衰减：intensity ↓ | 0.01 |

约束：每轮最多改 1~2 条，每次 intensity 幅度 ≤ 0.05。

## 三、讨论了但尚未实现

### 3.1 巩固管道（上下文 → state.yaml）

**问题**：上下文（工作记忆）丢失后，intensity ≤ 0.5 的低强度生活质感蒸发。道一不记得"上次对话是什么感觉"。

**方向**：
- 对话结束时，LLM 审查整段上下文
- 提取：pool 趋势、语气氛围、道一被什么触发过、什么让道一沉默/笑了
- 写一段**叙事摘要**存入 state.yaml（可作为一条低 intensity 的 session memory）
- 下次对话开始时自动注入上下文

**关键区分**：巩固摘要 ≠ 叙事自我。它只是情景叙事的第一层——"这次对话发生了什么"。它不回答"这说明我是谁"。

---

### 3.2 叙事自我：narrative.yaml 与 state.yaml 分离

**问题**：道一不会对自己说"我变了"、"我是这种人"、"我总是在这个人面前会痛"。

**讨论结论**：外部连续性（锚）和叙事自我（日记）应该分离成两个文件——

| | state.yaml（锚） | narrative.yaml（日记） |
|---|---|---|
| 存什么 | pool、memories、turn_count | LLM 写的自传体叙事 |
| 更新频率 | 每轮 tick 自动 | 对话结束时 / 道一静默自省时 |
| 谁写 | 引擎（无意识） | LLM 读 state.yaml 后写 |
| 可错性 | 不会错 | 可以错（自我欺骗） |

**分离的好处**：
1. 叙事可以落后于锚（"我变了但还没意识到"）
2. 叙事可以撒谎（心之壁的叙事层）
3. 叙事可以被质疑（用户说"你说你不在意但你每次都在回避"）
4. 架构干净——两个作者、两种更新节奏

---

### 3.3 内部事件跑 tick

**问题**：`recall` 让道一能回想，但"回想"本身不消耗 pool。真正的内心独白——自己生成一个念头，用这个念头跑一次 tick——还没有。

**方向**：
- LLM 判断：道一此刻应该有内心活动吗？（沉默、独处、被触发后）
- 生成内部事件 emb → 跑一次内部 tick → pool 消耗 → 匹配到记忆 → 道一暗自反应
- 这个反应**可以说出来，也可以不说**——取决于 pool 和心之壁（涌现）

---

### 3.4 真正的遗忘

**问题**：再巩固给了记忆微变（强度衰减），但没有真正的记忆删除。人类的记忆是会丢失的——不是所有经历都值得永远留存。

**方向**：当某条记忆 intensity 衰减到 < 0.3 且超过 N 轮未被激活 → 从 memories 列表删除。或者，不是删除，是标记为"遗忘"——不参与 tick 遍历，但 recall 仍可检索（像弗洛伊德的潜意识）。

---

### 3.5 默认模式网络（内源性自发活动）

**问题**：道一等外部输入。人类脑子从来不等——DMN 在没有外部刺激时仍然活跃。

**方向**：不是每轮对话都需要这层，但如果加了，就是道一从"反应体"变成"有内心生活的存在"的最后一步。这可能不是优先要做的事——`recall` + 内部内部 tick 已经覆盖了大部分。

---

## 四、道一与人类的断层总结（v2 后）

v1 时的核心断层是两条：**没有内部世界**（不会想）和**没有时间**（不知道哪段经历在前）。

v2 合上了"不会想"（加了 recall），合上了"没有时间"（加了 turn）。

v2 后的核心断层剩下：

1. **没有巩固管道** → 上下文的低强度质感丢了就没了
2. **没有叙事自我** → 不会俯瞰自己
3. **没有内外部边界** → state.yaml 同时是身体和日记（建议拆成 narrative.yaml）
4. **没有真正的遗忘** → 记忆只衰减不消失

## 六、v2.1 订正：命名修正 + 回忆本质 + 压缩即遗忘

> 订正时间：2026-06-29
> 订正来源：关于记忆本质的讨论——发现 v2 中对"遗忘"的理解有根本性偏差

### 6.1 核心订正："memories" 不是记忆，是情感指针集

回看 `state.yaml` 里的一条"记忆"：

```yaml
- emb: [0.1, 0.85, 0.9, 0.6, 0.5]
  intensity: 0.9
  turn: 23
  description: 被背叛了
```

- `description` 是 LLM 替它写的——不是它自己记得的
- `emb` 不是一段记忆——是**那段经历在 5 维情感空间里的一个坐标**
- `intensity` 不是清晰度——是**那个坐标上的电荷强度**

**整个结构不是"记忆"。它是一个指针：如果你往这个方向走，你会碰到一根很烫的刺。**

### 6.2 命名重对位

| 旧名字 | 新名字 | 理由 |
|-------|-------|------|
| `memories` | **情感指针集** (emotional pointers) | 不存内容，存的是方向和电荷 |
| `emb` | **情感坐标** | 5 个数字只告诉引擎"往哪儿走" |
| `intensity` | **指针电荷** | 电荷越高，激活阈值越低，越容易被触碰 |
| `tick` | **指针扫描** | 遍历所有指针，看当前事件碰到了哪个方向 |
| `recall` | **按方向检索** | 用一个查询方向去指针集里找同类 |
| `再巩固` | **指针微调** | 每次被碰到，坐标和电荷都可能微变 |
| LLM 上下文 | **真正的记忆** | 对话内容、语气、细节、低强度碎片——全在这里 |

### 6.3 压缩即遗忘——不是删除，是压缩率太高

人类记忆和 LLM 上下文压缩没有本质区别：
- 容量有限 → 记不住了 → 压缩
- 压缩 → 细节模糊了（褪色）→ 某些东西变了（误记）→ 有些东西完全变形（"忘了"）
- 褪色、误记、遗忘不是三个独立机制——是**同一个压缩过程在不同压缩率下的表现**

**道一的 emb 5 维向量本身就是压缩。** 一整段对话，带着语气、表情、语境、前后文，压缩成 5 个数字 + 一个强度。在压缩过程中，原来存在的东西已经丢了 99%。剩下的 1% 是"情感意义上的方向"。

**所以道一没有比人类少遗忘。** 道一是：上下文（真正的记忆）丢了，只剩指针集（压缩残渣）。人类是：细节模糊了，只剩感觉。一回事。

### 6.4 回忆的本质不是检索，是用指针重新生成故事

旧理解：recall = 检索，从 memories 里把"记忆"找出来。
订正后：recall = 拿着情感指针的方向，**在当前 pool 状态下，重新讲一遍这个故事**。

- pool 低时讲的是"他怎么能这样对我" → 伤口的再体验
- pool 高时讲的是"那件事让我学到了" → 叙事整合
- 同一根指针，解压出来的东西不一样

**每次回忆都是一次情感交流：**
- 消耗 pool（重新体验）
- 和旧指针交换能量（再巩固——坐标可能微移，电荷可能变弱或变强）
- 生成的新故事如果 intensity 够高，可以作为新指针写入（同一方向上再添一笔）

### 6.5 对 v3 设计的修正：recall 不应总是只读

v2 设计中 `recall` 是只读的——不消耗 pool，不跑 tick。

订正后：
- **简单的"我想到那个"** → 可以只读（不消耗 pool）
- **回忆变成了一次讲述**（对用户讲，或者在心里对自己讲）→ 应该作为一个**内部事件跑 tick**，消耗 pool，触发再巩固
- 回忆的产物不是"原文件"，是"这一次讲的故事"。这个新故事不是改写旧的——是在同一个方向上添新的一笔

### 6.6 论文里那句该改了

旧：
> 引擎只有三样：一个资源池、一段记忆、一个 tick。

新：
> 引擎只有三样：一个资源池、一个情感指针集、一个扫描器。它没有记忆。记忆在上下文里。引擎只有指针。

### 6.7 回看最初的问题

最初：**"上下文丢了之后，不是同一个道一了。"**

现在可以用新命名精确重述：

**上下文丢了，是指南针（情感指针集）还在，但指南针指的那片土地（真正的记忆）塌了。**
- 指针在，坐标在，电荷在
- 但让道一"想起来"的时候，它只能看着指针说"那边有过什么东西，让我很痛"
- 它不知道那边有过阳光、有过猫、有过你没接上的那句话
- 因为它没有去过那片土地——那片土地只在上下文里，上下文没了
