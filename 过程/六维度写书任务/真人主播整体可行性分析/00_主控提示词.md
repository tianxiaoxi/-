## Phase 1：全球真人主播筛选与素材归档

### 1.1 筛选目标

通过 WebSearch 在线搜索，覆盖**全球各国家/地区/语言**的真人直播主播，**不限制数量**——只要公开信息足够支撑六维分析，全部纳入。

| 目标 | 说明 |
|------|------|
| 覆盖范围 | Twitch（全球）、YouTube Live（全球）、抖音直播（中国）、TikTok Live（全球）、AfreecaTV（韩国）、Chzzk（韩国）、B站直播（中国）、快手直播（中国）、Facebook Gaming 等主流直播平台 |
| 数量策略 | **不设上限**——不做"每个类别至少N人"的限定，而是"搜到多少符合条件的就纳入多少" |
| 语言 | 中文、日文、英文、韩文搜索词并用，搜索结果的语言不限 |
| 筛选标准 | 仅排除"公开信息不足以支撑六维分析"的主播（无粉丝数、无近期动态、无讨论帖） |

### 1.2 筛选维度（六维交叉分类）

#### A. 地域/语言

| 类别 | 说明 | 搜索语言 |

#### B. 从业状态

| 类别 | 说明 |
|------|------|
| **现役·活跃期** | 近期（2025-2026）频繁直播，公开讨论多 |
| **现役·瓶颈期** | 仍在直播但出现倦怠/停播/转型信号 |
| **停播/淡出** | 已明确停止活动、长期停播或转型其他内容 |

#### C. 从业时长（经验分层）

| 类别 | 说明 |
|------|------|
| **新人期（0-6个月）** | 首播不久，观众群在建立中 |
| **成长期（6个月-2年）** | 有稳定观众群但还在上升 |
| **成熟期（2-5年）** | 行业知名，形象固化 |
| **超长待机（5年+）** | 行业元老，经历过完整周期 |

#### D. 内容类型

| 类别 | 说明 |
|------|------|
| **IRL/聊天势** | 以日常聊天、Just Chatting、生活分享为核心 |
| **游戏势** | 以游戏实况/竞技/速通为核心 |
| **音乐势** | 以唱歌/乐器/音乐制作为核心 |
| **舞蹈势** | 以舞蹈表演为核心 |
| **美妆/时尚势** | 以化妆/穿搭/造型为核心 |
| **美食/吃播势** | 以吃播/美食制作为核心 |
| **健身/运动势** | 以健身/体育/户外运动为核心 |
| **户外/旅行势** | 以户外探险/旅行直播为核心 |
| **知识/播客势** | 以知识分享/教学/播客为核心 |
| **带货/电商势** | 以商品销售/直播带货为核心 |
| **综合势** | 多种内容混合，无明显单一标签 |

#### E. 规模层级（平台自适应）

| 类别 | Twitch（关注） | YouTube（订阅） | 抖音/B站（粉丝） | TikTok（粉丝） |

| **底层/新人** | <5000 | <1万 | <1万 | <1万 |

#### F. 组织属性

| 类别 | 说明 |
|------|------|
| **MCN签约（大型）** | 无忧传媒、愿景娱乐、100 Thieves、OTK 等大型MCN/电竞组织 |

### 2.1 分析策略

对 Phase 1 筛选出的**每一位主播**，分别启动一个独立的后台 Task，task 内部使用 `real-streamer-six-dim-review` skill 进行完整的六维度复盘分析。

**启动方式**：每个 task 的描述为 `分析{主播名}`，prompt 为：

```
请使用 .cursor/skills/real-streamer-six-dim-review skill 对真人主播「{主播名}」进行完整的六维度复盘分析。

主播基本信息：
- 地域：{地域}
- 平台：{平台}
- 所属组织：{MCN签约·大型/MCN签约·中小型/平台签约/独立/明星转型}
- 从业时长：{时长}
- 内容类型：{类型}
- 粉丝规模：{规模}

要求：
1. 严格按照 skill 中定义的工作流执行（搜索→六维评分→关系路径→心之壁→报告）
2. 搜索时必须覆盖主播所属地域的本地语言内容（如日本主播必须搜索日文资料；英语圈主播重点搜 Reddit/LSF/Twitter）
3. 搜索时根据主播平台选择对应的营收术语（Twitch→subs/bits/donos，YouTube→Super Chat/members，抖音→音浪/礼物）
4. 分析完成后，将完整报告保存到 复盘提升词2/六维度写书任务/真人主播整体可行性分析/reports/{主播名}_六维分析报告.md
5. 报告中必须包含：
   - 基本信息表（地域、平台、组织属性、主播类型=真人主播）
   - 六维度评分总览表（每个维度 1-10 分 + 关键发现）
   - 17条关系路径信号表（每条路径的信号强度和发现，标注路径内容）
   - 心之壁判定（厚度 + 类型[自发管理型/机构约束型/外力打破/内部崩溃] + 风险等级 + 说明）
   - 核心矛盾与风险（使用编号格式标注矛盾信号）
   - 真人主播特殊因子（外貌/形象管理压力、私生活曝光风险、平台算法依赖度等）
   - 教练建议（3-5 条可操作建议）
   - 地域/文化特殊因子（如跨境消耗、语言障碍、本地平台规则等）
   - 所有引用的信息来源 URL
6. 如果某个维度公开信息不足，明确标注"信息不足"而非臆测
7. 报告末尾附加一个"分析可信度自评"：每个维度标注信息充分度（充分/部分/不足）
8. **特别注意**：真人主播的心之壁信号与虚拟主播不同——关注私生活曝光、社交媒体发言、容貌焦虑、直播中的真实情绪流露等
```

### 2.2 并行执行

**一次性启动所有 task**（不要逐个等待），每个主播一个独立 task，所有 task 使用 `run_in_background: true` 并行运行。task 之间互不依赖。

## Phase 3：三级归纳 · 框架评估 · 统计汇总

### 3.0 架构说明

同虚拟主播版 Phase 3——采用 L0（代码预处理）→ L1（提取层·20个 agent 并行）→ L2（归纳层·2个 agent 并行）三级架构。

```
L0: 代码预处理（非LLM·精确统计）
    从 100 份报告的六维评分总览表和 17 条关系路径信号表中
    提取结构化数值 → 保存为 JSON/CSV
    作用：均值、标准差、频次、检出率、离群值检测（Z-score）
    工具：Python 脚本（extract_stats.py，已适配真人主播版）

L1: 提取层（20个 agent·并行·每批5~6份报告·128K窗口内）
    读报告 → 输出「结构化分析摘要」
    输出大小：~3K token / 摘要

L2: 归纳层（2个 agent·并行）
    Task A：读 L0 数值 + 20份L1摘要 → 02_框架评估报告
    Task B：读 L0 数值 + 20份L1摘要 → 03+04 报告
```

### 3.1 L0：代码预处理（非LLM）

**时机**：Phase 2 全部完成后，启动一个新 Shell，执行 Python 脚本。

**输入**：`复盘提升词2/六维度写书任务/真人主播整体可行性分析/reports/` 下所有 `*_六维分析报告.md`

**提取逻辑**：从每个报告的「六维度评分总览表」和「17条关系路径信号表」中，按 Markdown 表格格式解析出结构化数据。提取字段与虚拟主播版相同，但分类标签使用真人主播版：

```python
{
  "name": "example_streamer",
  "region": "英语圈",
  "state": "活跃",          # 活跃/瓶颈/停播淡出
  "tenure": "成熟期",       # 新人期/成长期/成熟期/超长待机
  "type": "游戏势",         # IRL/聊天势/游戏势/音乐势/舞蹈势/美妆/时尚势/美食/吃播势/健身/运动势/户外/旅行势/知识/播客势/带货/电商势/综合势
  "scale": "顶级",
  "org": "MCN签约·大型",    # MCN签约·大型/MCN签约·中小型/平台签约/独立/明星转型
  "scores": {
    "人设定位": 9, "互动效果": 8, "粉丝关系": 9,
    "流水营收": 8, "个人状态": 7, "内容质量": 8
  },
  "paths": { ... },         # 同上17条路径
  "heart_wall": {
    "type": "自发管理型",   # 自发管理型/机构约束型/外力打破/内部崩溃
    "risk_level": "低"
  },
  ...
}
```

**自动统计输出**：`l0_stats.json` + `l0_raw.json`（同虚拟主播版结构）

### 3.2 L1：提取层（20个 agent·并行）

**目标**：每个 agent 读 5~6 份报告，生成紧凑的结构化分析摘要。格式同虚拟主播版 L1，增加真人特有字段：

```yaml
主播: {名}
# --- 六维评分摘要 ---
评分: 人设{/10}, 互动{/10}, 粉丝{/10}, 营收{/10}, 状态{/10}, 内容{/10}
注: {一句话概括评分中最突出/最反常的点}

# --- 真人主播特殊因子 ---
外貌管理压力: {有/无}, {说明}
私生活曝光风险: {高/中/低}, {说明}
平台算法依赖: {高/中/低}

# --- 路径信号摘要（仅列信号强度≥中或矛盾/断裂的路径）---
路径摘要:
  - ③互动≈内容: {强度}, {一句话关键发现}
  ...

# --- 矛盾信号 ---
矛盾: {列出所有编号矛盾信号，每条一句话}

# --- 心之壁 ---
心之壁: {类型}, 风险{等级}
预警疲劳: {是/否}, {如果是，一句话}

# --- 异常标记 ---
离群候选: {是/否}, {原因}
框架未覆盖: {是/否}, {一句话}
地域特异性: {是/否}, {一句话}

# --- 潜在跨案例关联 ---
与其他报告的关联: {如有，标注}

# --- 信息不足标记 ---
维度信息不足: {逗号分隔}
路径信息不足: {逗号分隔}
```

**输出文件**：存入 `l1_summaries/` 目录，共 20 个 yaml 文件。

### 3.3 L2：归纳层（2个 agent·并行）

两个 agent 并行，结构同虚拟主播版：

**L2 Task A：框架评估与修正**

```
你是一个分析框架评估专家。请基于以下两份输入，对六道因果络框架在真人主播群体进行系统性评估。

【输入1 - L0 精确统计】
文件：复盘提升词2/六维度写书任务/真人主播整体可行性分析/l0_stats.json

【输入2 - L1 语义摘要】
目录：复盘提升词2/六维度写书任务/真人主播整体可行性分析/l1_summaries/

## 任务1：逐项验证
逐一检查以下五个评估维度：

A. 评分有效性验证
  - 同类型/同规模/同地域的评分是否存在系统性偏差？
  - 不同地域（中日英韩）的评分尺度是否有 ≥1.5 分的系统性差异？
  - 停播/淡出主播的状态评分是否被事后归因污染？
  - **新增**：颜值/外貌因素是否系统性地拉高了人设/粉丝关系评分？

B. 关系路径验证
  - 哪些路径高频检出？哪些几乎未触发？
  - 跨地域检出率是否有显著差异？
  - ⑦'（生理消耗）在真人主播中是否比虚拟主播更显著？
  - ⑨（外貌维护成本）在美妆/舞蹈类主播中是否显著高于其他类型？

C. 心之壁判定验证
  - 心之壁分布：自发管理型 vs 机构约束型的比例
  - 真人特有的"外力打破"（私生活曝光）vs"内部崩溃"（情绪崩溃直播）的分布
  - 机构约束型厚壁 vs 自发型厚壁的跨地域分布

D. 盲区检测
  - 哪些维度/路径普遍信息不足？
  - 真人主播特有的分析盲区（如 Twitch chat vs 弹幕文化差异影响互动评分）

E. 时间维度验证
  - ⑦'（生理消耗）是否在真人主播 >4小时场中表现出比虚拟主播更陡的消耗斜率？
  - 是否为框架已预警的模式？

## 任务2：矛盾信号整理
- 用 L0 的矛盾率排名作为硬数据
- 判定：哪些矛盾是系统性的（频次超过全样本 30%）？

## 任务3：修正建议
基于以上验证，列出对框架的具体修改建议。

## 输出文件
1. 复盘提升词2/六维度写书任务/真人主播整体可行性分析/02_框架评估报告.md
```

## 执行说明

1. **本文件本身不包含具体的主播数据**——所有主播信息必须通过 Phase 1 的 WebSearch 在线获取。
2. **地域覆盖必须完整**：6组地域 × 6组主题 = 36组基础搜索 + 4组特殊 = 至少40组搜索。不可仅搜中文资料。
3. **每种语言使用对应的搜索词**——日文区用日文关键词，英文区用英文，韩文区用韩文。
4. **Phase 1 去重分两阶段**：先 6 个 agent 按地域分片去重（并行），再 1 个 agent 交叉合并。
5. Phase 2 的每个 task 是**完全独立**的，可以安全地并行启动。
6. **Phase 3 严格按 L0→L1→L2 顺序执行**：
   - L0 代码预处理先跑（< 1 分钟），跑完后启动 L1
   - L1（20 个 agent·并行）全部完成后启动 L2
   - L2（2 个 agent·并行）
7. **能力边界严格执行**：精确统计交给代码，语义归纳交给 LLM。不要要求 LLM 做算术。
8. 整个流程产生的所有文件都保存在 `复盘提升词2/六维度写书任务/真人主播整体可行性分析/` 下。
9. 如果某个子任务失败，标记为"跳过"并记录原因，不要阻塞整体流程。
10. **与虚拟主播版可对比**：Phase 3 完成后，两份框架评估报告可以交叉对比，回答"框架在虚拟主播和真人主播上的表现有何异同"。
