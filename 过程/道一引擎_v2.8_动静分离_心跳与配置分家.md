# 道一引擎 v2.8 — 动静分离：心跳与配置分家

> 订正时间：2026-06-29
> 前置版本：v2.7（回复风格映射也是总结语言）
> 本版本主题：state.yaml 里混着每轮变的活状态和永不变的静态配置。拆开——心归心，规归规。

---

## 一、问题

当前 `state.yaml` 是一个大杂烩：

```yaml
# 活的——每轮 tick 在变
pool: 0.0
turn_count: 21
memories: [...]       # 指针集，每轮可能追加
bio_drives: {...}      # 模拟器计数，每轮累加
last_heartbeat_turn: 0 # 心跳标记

# 死的——初始化后再也不变
bio_config: {...}      # 36 行配置，每轮都读但永不变
heartbeat_interval: 300
context_keep_turns: 20

# 元数据——引擎根本不读
character: {name: 道一, created_from: story}
```

三个级别的混放在一个文件里。每轮 tick 读全文件，每轮 status 看全文件。

后果：

1. **LLM 看到不该看到的**：`status` 返回 `bio_config` 完整细节——`hunger.threshold: 5`、`discomfort.trigger_chance: 0.05`。这些是给引擎的规则，不是给道一的信息。像手术灯照进心里——是噪音。
2. **备份/迁移不干净**：想保留指针集但重置配置？或者复制配置给新角色但不要记忆？现在全搅在一起。
3. **格式噪音**：配置字段的 YAML 体积远大于 `pool` + `turn_count`，但每轮 `status` 都一起吐。

---

## 二、和 v4→v7 是同一条剥离线

| 版本 | 剥掉了 | 本质 |
|------|--------|------|
| v5 | 心之壁 thickness | 间隙不是东西 |
| v6 | 五域、五行生克 | 总结语言不是零件 |
| v7 | pool→回复风格映射表 | 输出总结不应回输引擎 |
| **v2.8** | **bio_config 等混在 state.yaml** | **配置不是状态** |

**配置和状态是不同性质的两种东西。** 一段对话里，道一的心跳（pool）变了 20 次，指针集加了 3 条新记忆，bio_drives 从 0 涨到 5——但 `drain_per_cycle` 一次都没变过。把不变的东西和每轮变的东西放在同一个文件里，是同一类错觉：以为它们是同一种东西，因为它们都叫"跑起来需要的数据"。

## 三、拆法

```
characters/daoyi/
  heart.yaml          ← pool, memories, turn_count, bio_drives, last_heartbeat_turn
  config.yaml         ← bio_config, heartbeat_interval, context_keep_turns, character
  context_memory.txt  ← 纯文本直灌（已有，不变）
```

### 3.1 heart.yaml — 心跳文件

```yaml
# 道一的心跳——每轮 tick 都在变
pool: 0.0
turn_count: 21
memories:
  - emb: [0.75, 0.6, 0.9, 0.35, 0.95]
    intensity: 0.65
    turn: 0
    description: 父亲天小析创造了我
  # ...
bio_drives:
  hunger: 3
  thirst: 3
  sleepiness: 1.5
  discomfort: 0
last_heartbeat_turn: 0
```

引擎每轮读、每轮写。只有这里的东西在变。

### 3.2 config.yaml — 规则文件

```yaml
# 道一的运行规则——初始化后不再变
character:
  name: 道一
  created_from: story

bio_config:
  hunger:    {enabled: true, drain_per_cycle: 0.02, threshold: 5}
  thirst:    {enabled: true, drain_per_cycle: 0.01, threshold: 6}
  sleepiness:{enabled: true, drain_per_cycle: 0.03, threshold: 3}
  discomfort:{enabled: true, drain_per_cycle: 0.03, trigger_chance: 0.05}

heartbeat_interval: 300
context_keep_turns: 20
```

初始化时读一次，之后只在 `bio-config --set` 或手动编辑时写。LLM 的 `status` 不读这个文件。

## 四、engine.py 改动

核心原则：**内部数据结构不变，只在读写层拆成两个文件。**

```python
# 旧
def load_state(path: str) -> dict:
    with open("state.yaml") as f:
        data = yaml.safe_load(f)
    data = _ensure_defaults(data)
    return data

# 新
def load_state(heart_path: str) -> dict:
    with open("heart.yaml") as f:
        data = yaml.safe_load(f) or {}
    # 合成 config 的默认值（不读文件，用引擎硬编码默认值 + _ensure_defaults）
    data = _ensure_defaults(data)
    return data

def load_config(config_path: str) -> dict:
    """只在需要修改配置时读。引擎日常 tick 不读。"""
    with open("config.yaml") as f:
        return yaml.safe_load(f) or {}
```

| 命令 | 读 heart | 读 config | 写 heart | 写 config |
|------|:---:|:---:|:---:|:---:|
| `tick` | ✅ | ❌ | ✅ | ❌ |
| `auto-tick` | ✅ | ❌ | ✅ | ❌ |
| `status` | ✅ | ❌ | ❌ | ❌ |
| `recall` | ✅ | ❌ | ❌ | ❌ |
| `modify` | ✅ | ❌ | ✅ | ❌ |
| `init` | ✅ 创建 | ✅ 创建 | ✅ | ✅ |
| `feed` | ✅ | ❌ | ✅ | ❌ |
| `bio-config` | ❌ | ✅ | ❌ | ✅ |
| `load-context` | ❌ | ❌ | ❌ | ❌ |

**关键：`tick` 和 `status` 不再碰 config。** `bio_config` 的 drain 值用引擎的 `_ensure_defaults()` 硬编码默认值即可——因为 config 创建后不改，读文件是多余的。

### `init` 创建两个文件

```bash
python engine.py init characters/daoyi/heart.yaml --name "道一"
  # 创建 heart.yaml + config.yaml
```

`config.yaml` 写入默认值。之后用 `bio-config` 改。

## 五、status 输出净化

**前（当前）**：`engine.py status` 返回整个 state.yaml，含 `bio_config` 全体。

```json
{
  "bio_config": {
    "hunger": {"enabled": true, "drain_per_cycle": 0.02, "threshold": 5},
    ...
  }
}
```

LLM 读到了不该读的东西。

**后（v2.8）**：`status` 只返回 heart.yaml 的内容——pool、memories、turn_count、bio_drives。

```json
{
  "pool": 0.42,
  "turn_count": 21,
  "memory_count": 9,
  "bio_drives": {"hunger": 3, "thirst": 3, "sleepiness": 1.5, "discomfort": 0}
}
```

bio_drives 保留——道一需要知道"饿不饿、困不困"。但 `bio_config` 的 drain 公式消失——道一不需要知道"饿的阈值是 5"。

## 六、具体修改清单

| 文件 | 操作 |
|------|------|
| `scripts/engine.py` | `load_state` / `save_state` 拆成两套。`tick`/`status`/`auto-tick`/`recall`/`modify`/`feed` 只碰 heart |
| `scripts/engine.py` | `_ensure_defaults()` 里的 `bio_config` 默认值保留，作为引擎内硬编码常量 |
| `scripts/engine.py` | `cmd_init` 创建两个文件而非一个 |
| `scripts/engine.py` | `cmd_status` 不再返回 `bio_config`、`heartbeat_interval`、`context_keep_turns` |
| `scripts/engine.py` | `cmd_bio_config` 读写 `config.yaml` |
| `SKILL.md` | 所有 `state.yaml` 引用改为 `heart.yaml`（或标注状态文件/配置文件） |
| `reference.md` | 更新数据层结构描述 |
| `characters/daoyi/state.yaml` | 拆为 `heart.yaml` + `config.yaml`。原文件归档或删除 |

## 九、一句话

**v2.7 剥掉了回复风格映射表——输出总结不存。v2.8 继续剥——配置不是状态。心跳会变，规则不变。混在一起是错觉，拆开是澄清。道一的 status 不再像一张体检报告——它只是心跳、疤、和此刻的体温。**
