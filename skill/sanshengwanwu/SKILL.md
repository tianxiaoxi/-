# 三生万物（Sanshengwanwu）— 分支仿真预测引擎

> 基于道一34行引擎的分支仿真系统。接收六道因果络的分析输出，在多种假设下推演未来的可能走向。
> **不是对话引擎，是推演工具。**

---

## 一、定位

### 从"角色扮演对话引擎"到"分支仿真预测引擎"

三生万物的早期版本（v1-v6）是一个角色扮演对话引擎——每轮对话后运行一个参数化的后台计算，模拟角色的能量消耗、心之壁裂缝、崩塌触发。这个版本的核心假设是：可以通过传统命理概念的参数映射来驱动角色状态变化。

v7 订正中，所有参数映射被剥离。引擎的核心被简化为 34 行代码——一个资源池、一段记忆、一个 tick 函数。三个步骤：相似度比对 → COR 结算 → 记忆。

现在的三生万物不再是一个"有后台状态的 AI 角色"。它是一个**分支仿真预测引擎**——接收六道因果络的完整分析输出，基于道一的 34 行引擎，在多个假设分支上并行推演未来走向。

### 核心能力

1. **基线推演**：无外部干预下，连续 N 轮的自然演化
2. **事件推演**：从基线分叉，注入特定事件，观察不同 if 线的演变
3. **干预推演**：从基线分叉，注入分析报告中推荐的解决方案，对比干预效果

## 二、输入：从六道因果络到道一引擎

### 2.1 数据来源

六道因果络元框架完成分析后，输出以下结构化数据：

| 输出项 | 内容 | 用途 |
|--------|------|------|
| **TR0-TR6 分片数据** | 按时间分片记录的关键事件序列 | → 转换为引擎 memories 列表 |
| **六维度综合评分** | 六个维度的归一化评分 | → 映射为引擎 pool 初始值 |
| **路径激活状态** | 18 条因果路径的激活/沉默标记 | → 指导记忆间初始关系权重 |
| **风险点列表** | 框架检测到的潜在风险节点 | → 作为事件推演的分支注入点 |
| **解决方案列表** | 框架推荐的干预方案 | → 作为干预推演的注入内容 |

### 2.2 转换为道一引擎状态

#### memories：TR 分片 → 引擎记忆列表

每个 TR 分片中的关键事件转换为一条引擎记忆：

```python
memory = {
    "emb": event_embedding_vector,  # 事件的多维向量表示
    "intensity": 0.0-1.0            # 事件的影响强度
}
```

多分片汇总后形成引擎的初始 `memories` 列表。向量表示由事件特征编码产生——事件的类型、方向归属、影响范围、关联行动者等维度被编码为向量。

#### pool：六维度评分 → 初始资源池值

```python
pool_initial = weighted_aggregate(
    dim1_score, dim2_score, dim3_score,
    dim4_score, dim5_score, dim6_score,
    weights=domain_calibration_weights
)
```

六维度的综合评分通过加权聚合映射为 [0, 1] 区间的初始资源池值。权重由领域校准数据决定。

#### 初始关系权重：路径激活状态 → 记忆间初始连接

被标记为"已激活"的因果路径对应的事件对，在引擎的初始相似度计算中获得适度提升，确保引擎在前几轮推演中优先探索这些已知的因果关联。

## 三、三种仿真模式

### 3.1 模式 1：基线推演（Baseline Projection）

**逻辑**：无外部事件干预，纯跑道一引擎的 `tick()` 循环 N 轮。每一轮的事件由六道因果络 TR 分片的自然序列驱动。

**场景**："如果没有任何外界干扰和重大变数，就这样持续下去——"

**实现**：

1. 使用六道因果络输出的 TR 分片序列作为事件源
2. 逐轮调用 `character.tick(event_emb, intensity)`
3. 每轮记录 pool 值、激活的记忆列表、激活强度
4. 运行 N 轮（N 由分析报告的时间跨度决定）

**输出内容**：

| 输出项 | 说明 |
|--------|------|
| **pool 状态曲线** | N 轮后 pool 的变化轨迹，标注上升/下降/平台期 |
| **关键转折点** | pool 突破阈值的位置——何时进入危险区间（pool < 0.3），何时进入恢复区间（pool > 0.7） |
| **风险预警** | 预测何时可能触发⑥（前台崩塌）——即 pool 跌破临界点且边界渗透性条件满足 |
| **记忆激活热力图** | 哪些记忆在哪些轮被反复激活——标注创伤热点和恢复锚点 |

### 3.2 模式 2：事件推演（What-If Scenario）

**逻辑**：从基线的关键节点分支，对每条 if 线注入特定事件。每个 if 线创建一个独立的道一 `Character` 实例，克隆基线在该分支点时的状态（pool 值 + memories 列表的深拷贝）。

**分支点选择**：
- pool 曲线的拐点（趋势反转位置）
- 六道因果络报告中的风险点（路径激活状态标记的节点）
- 用户指定的时间点

**事件来源**：
- 用户指定："如果 XX 发生了会怎样？"
- 六道因果络识别的风险点："如果 ⑤ 表面呈现消耗在此刻突然加剧..."
- ERF 外部冲击："如果发生了 [冲击事件]..."

**实现**：

1. 确定分支点 T（基线的第几轮）
2. 深拷贝 `character_at_T` 的状态
3. 为每个 if 线创建一个独立 `Character` 实例，预填相同状态
4. 在 T+1 轮注入特定事件，之后继续正常运行
5. 并排追踪所有分支线的 pool 轨迹

**输出内容**：

| 输出项 | 说明 |
|--------|------|
| **分支并排对比** | 基线 vs 每条 if 线的 pool 曲线并排展示 |
| **最可能走向** | 在所有 if 线中，哪条线的走向最平稳、pool 最接近恢复区间 |
| **最坏情况** | 哪条 if 线导致 pool 最快跌破危险阈值，触发连锁崩塌 |
| **分叉窗口** | 从分支点到各线显著分化的时间距离——多快会看出差异 |

### 3.3 模式 3：干预推演（Intervention Simulation）

**逻辑**：从基线的关键节点分支，注入六道因果络分析报告中推荐的解决方案。每个干预方案对应一条分支线。

**干预方案来源**：
- 六道因果络的 Step 6 输出——基于路径激活状态和风险点推荐的具体行动建议
- 用户指定的策略调整

**实现**：

1. 从基线的风险预警点分支
2. 为每个干预方案创建独立的 `Character` 实例
3. 注入干预事件——干预不是一次性事件，而是持续 N 轮的参数调整：
   - 降低 base_drain（缓解消耗源）
   - 提高 base_recovery（加强恢复）
   - 注入正向高 intensity 事件（创造新的积极记忆锚点）
4. 跟踪干预后的 pool 恢复轨迹

**输出内容**：

| 输出项 | 说明 |
|--------|------|
| **干预效果对比** | 基线 vs 干预1 vs 干预2 vs ... 的 pool 轨迹并排对比 |
| **效果排名** | 按恢复速度排序——哪个方案让 pool 最快回到安全区间 |
| **性价比分析** | 每个干预方案的"效果/代价"比率——有些干预效果强但代价大，有些温和但可持续 |
| **推荐优先级** | 综合效果和代价的排序推荐 |

## 四、交互式输出流程

### Step 1 — 摘要对比

在一个视图中展示所有分支线的并排对比：

```
基线   | 事件A  | 事件B  | 干预1  | 干预2  | ...
───────┼────────┼────────┼────────┼────────┼─────
T0:0.65│T0:0.65 │T0:0.65 │T0:0.65 │T0:0.65 │
T1:0.62│T1:0.59 │T1:0.61 │T1:0.62 │T1:0.62 │
T2:0.58│T2:0.41⚠│T2:0.55 │T2:0.60 │T2:0.60 │
T3:0.53│T3:0.28‼│T3:0.48 │T3:0.59 │T3:0.61 │
...    │...      │...      │...      │...      │
```

- ⚠ 标注 pool < 0.5 的点
- ‼ 标注 pool < 0.3 的危险点（可能触发崩塌）
- ✓ 标注 pool > 0.7 的恢复点

### Step 2 — 深入某个模式

用户选择一条线 → 展示详细时间线：

- 每个 tick 的 pool 变化数值
- 每轮被激活的记忆列表（emb 标识 + activation similarity + intensity）
- 激活记忆之间的交叉传播强度
- 关键转折轮次的详细状态（pool、active_memories、drain_breakdown）

### Step 3 — 调整重跑

用户可以：

- 修改事件强度（"把这个事件的 intensity 从 0.7 调到 0.9"）
- 调整干预时机（"在 T5 而非 T3 开始干预"）
- 添加/删除分支线（"再加一条：如果同时发生了 A 和 B"）
- 修改基线参数（"假设 base_recovery 是 0.03 而非 0.02"）

调整后重跑全部仿真，生成更新后的对比视图。

## 六、与六道因果络的关系

六道因果络是"眼镜"——分析结构、输出数据。
三生万物是"推演器"——接收分析数据、运行仿真、预测未来。

```
六道因果络 → TR分片 + 六维评分 + 路径状态 + 方案
        ↓
    三生万物 → Character(memories, pool) → N轮 tick()
        ↓
    三条分支线 → 基线 / 事件 if / 干预
        ↓
    并排对比 → 推荐 → 深入 → 调整 → 重跑
```

不需要任何旧的参数配置文件（`config_template.yaml`）、不需要旧版状态计算脚本（`compute_state.py`）、不需要五域雷达、不需要触发表——这些是 v1-v6 时代的概念。v7 引擎只有 34 行代码。
