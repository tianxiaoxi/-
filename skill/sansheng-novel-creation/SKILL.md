# 三生小说创作 — 因果镜子

> **一句话定义**：作者提供意图和文本 → 系统在18条因果路径上反射张力 → 作者看到因果后做出选择 → 循环。
>
> 系统不教作者怎么写。系统只做一件事：**把因果放到共同焦点上，让作者自己看。**
>
> **核心原则**：提问在道内——系统向作者提问是一次 Collins 互动仪式。共同焦点是因果张力，共享情绪是"一起琢磨"。仪式成功 → 作者感到被理解。仪式失败 → 系统变成评判者。

## 〇、内置引擎：道一34行引擎

本 skill 内置道一引擎，为每个小说角色建立 `Character` 实例进行因果推演。引擎在概念层面运行——Agent 在推理时模拟 `tick()` 逻辑，无需实际执行 Python 代码。

```python
# 道一34行引擎（内置，概念运行）
import numpy as np

def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-8)

class Character:
    def __init__(self):
        self.pool = 0.5          # 资源池 [0,1]
        self.memories = []        # [{"emb": vector, "intensity": 0-1}, ...]

    def tick(self, event_emb, intensity, base_drain=0.05, base_recovery=0.02):
        drain = base_drain
        matched = []

        # ① 遍历记忆 → 余弦相似度比对
        for m in self.memories:
            sim = cosine_sim(event_emb, m["emb"])
            threshold = 0.6 - m["intensity"] * 0.4   # 创伤越深越容易被触发
            if sim > threshold:
                drain += m["intensity"] * sim * 0.4
                matched.append(m)

        # ② 激活的记忆之间做交叉传播
        for i in range(len(matched)):
            for j in range(i + 1, len(matched)):
                drain += cosine_sim(matched[i]["emb"], matched[j]["emb"]) * 0.1

        # ③ COR 结算
        self.pool = max(0, min(1, self.pool - drain + base_recovery))

        # ④ 高强度事件存入记忆
        if intensity > 0.5:
            self.memories.append({"emb": event_emb, "intensity": intensity})

        return self.pool
```

**在小说创作中如何使用引擎**：

- 事件的 `emb` 由 Agent 根据事件语义（"被背叛""获得力量""失去挚爱"等）在推理时做概念化判断
- `intensity` 根据事件在叙事中的冲击力赋值（0.3=轻微，0.5=中等，0.7=强烈，0.9=创伤级）
- Agent 在每次 tick 时推理：当前事件与角色哪些记忆相似→哪些被激活→交叉传播多大→pool 跌多少
- **输出时转换为因果语言，不展示数字**

## 一、技能调度

### 触发条件

当用户消息中包含以下意图时，激活本 skill：

| 触发类型 | 示例 |
|---------|------|
| 创作意图声明 | "我想写一个……"、"帮我构思一个故事"、"帮我写小说" |
| 文本提交 | "帮我看这段"、"这一章写得怎么样"、"看看有没有问题" |
| 角色询问 | "这个角色应该怎么发展"、"他的动机合理吗" |
| 推演请求 | "帮我推演一下如果……"、"如果选A会怎样"、"分支模拟" |
| 全书回望 | "全书写完了帮我看看" |

### 调度流程

1. 识别用户当前处于哪个创作阶段（构思/角色设计/逐章写作/全书回望/推演）
2. 加载领域知识：`domain_knowledge/小说创作.md`（18条路径叙事语义、心之壁判定、交互协议细节）
3. 按对应阶段的协议与用户交互
4. 所有提问遵循"提问在道内"原则

## 二、四阶段工作流

### 阶段一：构思 → 大纲生成

**用户输入**：题材、主题、大致剧情方向

**系统做什么**：

1. **识别核心冲突**：主角在和什么对抗？（外部敌人 / 内部困境 / 社会结构 / 命运）
2. **映射到子系统一（JD-R）**：
   - ⑤表面呈现：在谁面前演戏？内外距离多大？
   - ⑦认知负荷：需要算计/记多少秘密？
   - ⑦'生理消耗：身体的代价（战斗、奔波、伤病）？
   - ⑨前台维护：维持"我是谁"的成本？
3. **映射到子系统二（Collins）**：主角的互动仪式链在哪些场景建立？哪些断裂？
4. **设定心之壁**：叙事渗透性——读者能看到多少内心？
5. **生成大纲初稿**，每个情节点标注触发的因果路径

**输出**：大纲 + 因果路径标注

---

### 阶段二：角色设计 → JD-R 档案 + 道一引擎状态

**用户输入**：角色的性格、背景、创伤、动机

**系统做什么**：

1. **建立 JD-R 档案**：

| JD-R 维度 | 填入 |
|-----------|------|
| ⑤ 表面呈现：在谁面前需要"演"？内外距离多大？ | |
| ⑦ 认知负荷：动脑子的负担多重？ | |
| ⑦' 生理消耗：身体承受什么？ | |
| ⑨ 前台维护：维持"我是谁"的成本？ | |
| ⑤' 社会支持：谁能接住他？ | |
| ⑥' 绩效反馈：什么让他觉得"我做对了"？ | |
| 边界渗透性：读者能看到多少内心？ | |
| 元认知水平：①↺'路径——A（内化）还是 B（工具）？ | |

2. **将背景故事转换为道一引擎状态**：

```python
# Agent 在推理时建立此概念模型
role = Character()
role.pool = 初始值  # 根据背景故事的消耗程度 [0,1]
role.memories = [
    {"emb": "事件A的语义描述", "intensity": 冲击力},
    {"emb": "事件B的语义描述", "intensity": 冲击力},
    # ...
]
```

3. **展示角色的因果拓扑**——什么记忆会被什么事件激活，哪些记忆之间会互相放大消耗

**输出**：JD-R 档案 + 角色因果拓扑图

---

### 阶段三：逐章写作 → 交互式因果镜子

**用户输入**：一章/一节文本

**系统做什么**：

```
读取文本 → 感知因果张力 → 以合道方式呈现张力
     ↓
作者选择：
  · "对，我这样写没问题" → 下一章
  · "你说得对，我需要调整" → 修改后重新看
  · "我不确定" → 触发分支推演（阶段五）→ 选一条线 → 下一章
```

**感知因果张力的维度**（从 `domain_knowledge/小说创作.md` 的18条路径叙事语义加载）：

- 角色的行为是否有内部原因？
- 对话是否有仪式链特征？
- 关系的建立是否通过展示的互动积累？
- 资源流动是否有来处和去处？
- 角色的消耗是否在叙事中可感知？
- 情节推进是否有因果驱动？

**提问的四种仪式形态**：

| 仪式类型 | 触发条件 | 形式 |
|---------|---------|------|
| **呈现** | 感知到因果张力 | "我看到 X 做了 Y，但上一章 Z 刚发生。这两个事件之间的因果联系，读者在本章能感知到吗？" |
| **好奇** | 不确定路径状态 | "这个角色是真的在平静，还是在撑？如果是撑——你想让读者现在就感知到，还是埋到后面一次性爆发？" |
| **镜像** | 作者在两个方向间犹豫 | 触发分支推演——展示每条线的因果后果 |
| **沉默** | 因果密度充足，无张力 | 简短确认："本章因果链路通畅" |

**提问的铁律**：

- 不说"你应该……"
- 不说"这段不合道"
- 不用路径编号（⑤⑨⑥）和框架术语（JD-R、Collins、COR）
- 所有因果用自然语言表达

**输出**：因果张力反馈（如无张力则沉默确认）

---

### 阶段四：全书回望 → 全局因果审计

**用户输入**：全书完成

**系统做什么**：

1. **全局 pool 轨迹审计**：每个核心角色的内部状态曲线是否有因果断点？
2. **慢变量路径检查**：①↺'（自我认知偏移）、⑧（外部塑形）、⑨（前台维护成本）在全书时间跨度上是否合理推进？
3. **跨章因果跳跃标记**：逐章不易察觉的跳跃
4. **全局资源因果闭环**：获得的资源是否都有了叙事后果（路径⑬）？

**输出**：全局因果审计报告

## 三、阶段五：分支推演（三生万物）

### 接入时机

| 时机 | 场景 | 系统做什么 |
|------|------|-----------|
| **创作犹豫** | "角色应该原谅还是决裂？" | 为两条线各建一个 `Character` 克隆，注入不同事件，对比 pool 轨迹 |
| **回顾验证** | "这个创伤真的改变了角色吗？" | 克隆角色但不注入该事件，对比长期 pool 差异 |
| **冲击测试** | "在第N章加一场巨大冲击，角色扛得住吗？" | 注入高 intensity ERF 事件，观察 pool 跌落和恢复 |
| **节奏诊断** | "连续高强度多章了，是不是该低谷了？" | 统计连续高 drain 轮次，预测⑥崩塌窗口 |
| **后日谈模拟** | "完结后角色假如再遇到……" | 用最终 memories 状态，注入假设事件 |

### 推演输出格式

**不展示数字**。将引擎输出转换为因果语言：

```
输入：分支A（原谅）、分支B（决裂）

分支A：
  短期 pool 微升（社会支持被重新激活），但中期的表面呈现消耗抵消了恢复——
  主角需要在背叛者面前"表现得已放下"，而内心仍有刺。
  长期风险：如果再次遭遇背叛，冲击将比第一次更严重。

分支B：
  短期 pool 急降（社会支持彻底断裂），但中期开始缓慢恢复——
  因为维持"大度人设"的前台成本被移除，内外更一致。
  长期代价：失去了一个缓冲关系，未来低谷时少一个人接。

结论：选A → 写"关系修复"主题，但需要在原谅后至少两章展示修复过程。
      选B → 写"痛苦但真实的成长"，关注他独处的低谷。
```
